Which OWASP Top 10 edition and which categories does the Smartcat security checklist use?	The 2021 edition: A01 Broken Access Control, A02 Cryptographic Failures, A03 Injection, A05 Misconfiguration, A07 AuthN failures, A09 Logging/Monitoring, A10 SSRF.<br>These are the categories that appear most often in C# backend diffs.	ch13 security owasp smartcat
Security review severity logic: what MR status follows from the findings?	Any Critical &rarr; <code>changes_requested</code>.<br>Only Warning/Suggestion &rarr; <code>needs_review</code>.<br>No findings &rarr; <code>approved</code>.	ch13 security severity smartcat
How do Critical/Warning/Suggestion map to BLOCKER/MAJOR/MINOR?	Critical &asymp; BLOCKER (fix before merge), Warning &asymp; MAJOR (fix or explicit decision), Suggestion &asymp; MINOR (hardening).	ch13 security severity
Security checklist exclusions: how are test files, migrations and test-workflows treated?	<code>test-workflows/**</code>: skipped entirely (security team policy).<br>Tests and <code>*Migration.cs</code>: Critical downgraded to Warning.<br><code>*Example*</code>/<code>*Sample*</code>/<code>*Mock*</code>: Warning downgraded to Suggestion.	ch13 security severity smartcat
What do the six letters of STRIDE stand for?	Spoofing, Tampering, Repudiation, Information disclosure, Denial of service, Elevation of privilege.<br>Each breaks one property: authentication, integrity, non-repudiation, confidentiality, availability, authorization.	ch13 security stride threat-modelling
STRIDE: a client sends <code>UpdatedByUserId</code> in the request body and the server stores it. Which letter?	Spoofing: the client chooses who it is. Take the actor from the authenticated principal.	ch13 security stride
STRIDE: nobody can tell who deleted a project. Which letter, and what is the control?	Repudiation. Control: a structured audit entry with actor, tenant, target, action, result and time.	ch13 security stride audit
What is a trust boundary, and why is an internal Kafka event not automatically trusted?	A place where data moves from less trusted to more trusted. An event can carry an <code>accountId</code> that came from a user several hops earlier; trust depends on where the data came from, not on the network.	ch13 security stride threat-modelling
Why is tenant isolation the number one risk in a multi-tenant SaaS?	A cross-tenant read hurts a customer who did nothing wrong, is a reportable data breach, and one missing filter is enough to cause it.	ch13 security tenant-isolation
What is IDOR?	Insecure Direct Object Reference: the API accepts an object id and acts on the object without checking that the caller may access it.	ch13 security tenant-isolation idor
Why is a GUID id not an access control?	Ids leak through URLs, logs, shared links and tickets. Hard to guess is not the same as not allowed; the ownership check must be explicit.	ch13 security tenant-isolation idor
What is wrong with this repository method?<pre><code>public Task&lt;Project?&gt; GetProjectAsync(Guid projectId, CancellationToken ct) =&gt;<br>    _projects.Find(x =&gt; x.Id == projectId).FirstOrDefaultAsync(ct);</code></pre>	No tenant filter (Critical, <code>tenant-filter</code>). Any user who knows the id reads any account's project.<br>Fix: add <code>Eq(x =&gt; x.AccountId, accountId)</code> with the account from the authenticated context.	ch13 security tenant-isolation mongodb
Name the three forms of a tenant check.	1) Tenant filter in the query. 2) Ownership check after retrieval (compare tenant on the result). 3) Scoped pre-check: list the caller's resources first, then call the unscoped detail API (S14).	ch13 security tenant-isolation
Rule S2: what counts as a cross-tenant parameter gap?	<code>workspaceId</code>, <code>accountId</code>, <code>projectId</code>, <code>driveFileId</code> taken from the request and never compared with the authenticated context (BLOCKER).	ch13 security tenant-isolation smartcat
Rule S3: what is wrong with a sidecar path <code>/{conversationId}/{fileName}</code>?	One namespace for all tenants: paths can collide or be guessed across tenants (BLOCKER). Include <code>workspaceId</code> and the conversation/account in every sidecar path or storage key.	ch13 security tenant-isolation smartcat
Rule S13: how do you protect a route with a <code>{workspaceId}</code> string parameter?	Validate the format and fail closed: route constraint such as <code>{workspaceId:guid}</code> or <code>regex(...)</code>, or a first-line guard returning 400.	ch13 security tenant-isolation aspnetcore
Rule S18: what is the bug in <code>FindByUser() ?? FindByWorkspace() ?? FindByOrg()</code>?	The chain stops at the first non-null row even if it is disabled or empty. Filter <code>IsEnabled &amp;&amp; !IsEmpty</code> at every level.	ch13 security tenant-isolation credentials
Ownership mismatch: return 403 or 404?	404 when the id itself is sensitive: 403 confirms the object exists. Both are acceptable if consistent and deliberate.	ch13 security tenant-isolation
Why must a tenant-isolation test seed two tenants?	With one tenant the test cannot fail on a missing tenant filter. The second tenant is the whole point of the test.	ch13 security tenant-isolation testing
Rule <code>auth-all-roles</code>: what does it check?	That the permission check decides for every role: admin, manager, freelancer/vendor, external user, anonymous. Use an allow-list where unknown roles are denied.	ch13 security access-control smartcat
Rule S20: two patterns to flag on write endpoints?	1) <code>[HttpPost/Put/Delete/Patch]</code> without <code>[Authorize]</code> (action or controller).<br>2) Actor identity (<code>UpdatedByUserId</code>, <code>OwnerId</code>) read from the DTO instead of the principal.	ch13 security access-control aspnetcore
How do you make ASP.NET Core deny endpoints by default?	Set <code>AuthorizationOptions.FallbackPolicy</code> to a policy with <code>RequireAuthenticatedUser()</code>. Public endpoints then need an explicit <code>[AllowAnonymous]</code>.	ch13 security access-control aspnetcore
What is wrong here?<pre><code>var enabled = request.AccountFeatures.GetValue&lt;bool&gt;("IsAiPdfProcessingEnabled");</code></pre>	Rule S1 (BLOCKER): the feature flag comes from the request body, so the client decides access.<br>Fix: resolve server-side via <code>IFeatureService</code> for the authenticated tenant.	ch13 security feature-flags smartcat
Rule S4: why not store <code>IsXEnabled</code> on <code>AgentRun</code> in MongoDB?	The snapshot stays <code>true</code> after the flag is switched off. Re-resolve via <code>IFeatureService</code> on every read; background jobs get <code>accountId</code> and evaluate the flag.	ch13 security feature-flags smartcat
Rule S5: why is <code>static readonly AsyncLocal&lt;T&gt;</code> with a public setter a security issue?	Values flow into child tasks and background work and any code can change them, so tenant state can leak or be overwritten. Use scoped DI or <code>HttpContext.Items</code>.	ch13 security access-control async
At Smartcat (ai-agents): what is the canonical tenant identity type?	<code>PlatformUserContext</code> (<code>src/Module.Mcp/Auth/</code>). It has owners (auth middleware, task processor) and a fail-closed <code>GetRequiredWorkspaceId()</code>.	ch13 security tenant-isolation smartcat
Which algorithms are Critical findings under <code>weak-hash</code> and <code>weak-crypto</code>?	Hash: MD5, SHA1, RIPEMD160 for security purposes.<br>Cipher: DES, 3DES/TripleDES, RC2, RC4.	ch13 security crypto
Why is <code>System.Random</code> wrong for a reset token, and what is the replacement?	It is predictable. Use <code>RandomNumberGenerator.GetBytes(32)</code> and Base64URL-encode it; add expiry and single use.	ch13 security crypto
What is wrong here?<pre><code>var key = SHA256.HashData(Encoding.UTF8.GetBytes(passphrase));<br>aes.Key = key;</code></pre>	Rule S16 (MAJOR): a fast, unsalted hash as key derivation. Use PBKDF2 (<code>Rfc2898DeriveBytes.Pbkdf2</code>, high iterations) or Argon2id, with a per-key salt stored next to the ciphertext.	ch13 security crypto kdf
PBKDF2 vs HKDF: when do you use which?	PBKDF2/Argon2id: low-entropy input (passwords), slow and salted by design.<br>HKDF: input is already a strong random key; fast; derives several purpose-bound keys via <code>info</code>.	ch13 security crypto kdf
Why is <code>SHA256(password + salt)</code> still a bad password hash?	SHA-256 is fast: attackers test billions of guesses per second. Password hashing must be slow: PBKDF2, Argon2id, or Identity <code>PasswordHasher&lt;T&gt;</code>.	ch13 security crypto passwords
What is the main rule when using <code>AesGcm</code>?	Never reuse a nonce with the same key. Use a random 12-byte nonce per message, a 16-byte tag, and store <code>{keyId, nonce, tag, ciphertext}</code> together.	ch13 security crypto
A real API key was committed. What are the steps, in order?	1) Rotate/revoke the key. 2) Remove it from code and move it to the secret store. 3) Clean history if policy requires. Removing it from code alone fixes nothing.	ch13 security secrets interviewer
Rule S8: when is disabling TLS validation acceptable?	Never in deployed environments (BLOCKER). Only behind an explicit <code>IHostEnvironment.IsDevelopment()</code> gate with a clear comment; better to trust the dev CA.	ch13 security crypto tls
At Smartcat: is an internal API client on plain HTTP a finding?	Not by itself (calibration note). The finding is TLS added and then disabled, which looks safe but is not.	ch13 security tls smartcat
Four shapes of NoSQL injection with the MongoDB C# driver?	1) String-built <code>BsonDocument.Parse</code> filters. 2) <code>$where</code> JavaScript. 3) Operator objects (<code>{&quot;$ne&quot;: null}</code>) from untyped client JSON. 4) User-chosen field names and unescaped regex.	ch13 security injection mongodb
What is wrong here?<pre><code>var filter = BsonDocument.Parse("{ Email: '" + email + "' }");</code></pre>	NoSQL injection (Critical): the value becomes query structure. Use <code>Builders&lt;User&gt;.Filter.Eq(x =&gt; x.Email, email)</code>.	ch13 security injection mongodb
Safe &quot;name starts with&quot; MongoDB search: four parts?	Length cap, <code>&quot;^&quot; + Regex.Escape(q)</code>, <code>BsonRegularExpression(pattern, &quot;i&quot;)</code>, and the tenant filter combined with it.	ch13 security injection mongodb regex
How do you safely let the client choose a sort field?	Map an allow-list of public names to typed fields with a <code>switch</code>; reject unknown names with 400. Never pass the raw name to <code>Sort.Ascending(string)</code>.	ch13 security injection mongodb
Safe way to start a process with an argument that may contain spaces or quotes?	<code>UseShellExecute = false</code> and <code>ProcessStartInfo.ArgumentList.Add(...)</code> per argument; no shell. Also do not use user-chosen file names.	ch13 security injection
What does this return?<pre><code>Path.Combine("/data/uploads", "/etc/passwd")</code></pre>	<code>/etc/passwd</code>. <code>Path.Combine</code> discards earlier parts when a later argument is rooted.	ch13 security injection path-traversal
Correct containment check for a file path built from user input?	<code>Path.GetFullPath(Path.Combine(rootFull, relative))</code> then <code>StartsWith(rootFull + separator, Ordinal)</code>. The trailing separator stops <code>/data/uploads-evil</code>.	ch13 security path-traversal
Rule S9: correct order to sanitize a URL path for a sidecar proxy?	1) URL-decode. 2) Split into segments. 3) Reject <code>..</code>, <code>.</code>, empty, or segments containing <code>/</code> or <code>\</code>. 4) Re-encode each segment and join.<br>Checking <code>..</code> before decoding misses <code>%2e%2e</code>.	ch13 security path-traversal smartcat
What is wrong here?<pre><code>var s = new JsonSerializerSettings { TypeNameHandling = TypeNameHandling.All };<br>var obj = JsonConvert.DeserializeObject(body, s);</code></pre>	Unsafe deserialization: the JSON chooses which .NET type to create, a known remote code execution vector. Use <code>TypeNameHandling.None</code>, or allow-listed polymorphism (<code>[JsonDerivedType]</code> or a binder).	ch13 security deserialization
Rule S6: what is wrong with <code>element.GetProperty(&quot;enabled&quot;).GetBoolean()</code> on untrusted JSON?	It throws when the value is not <code>true</code>/<code>false</code> &rarr; 500 and possible DoS. Check <code>ValueKind</code> first; also set <code>MaxDepth</code> (for example 32).	ch13 security json validation
What is wrong here?<pre><code>catch (Exception ex) { return StatusCode(500, ex.ToString()); }</code></pre>	<code>stack-trace-exposure</code> (Critical): leaks stack, paths, driver errors. Use a central <code>IExceptionHandler</code> + ProblemDetails with a trace id; details only in logs.	ch13 security misconfiguration aspnetcore
Why is <code>SetIsOriginAllowed(_ =&gt; true).AllowCredentials()</code> dangerous?	Any website can make credentialed calls as the user and read the responses. It is the usual workaround after <code>AllowAnyOrigin()</code> + <code>AllowCredentials()</code> throws.	ch13 security cors aspnetcore
Is CORS an access control mechanism?	No. Browsers enforce it; server-to-server calls ignore it. It only decides which origins may read responses in a browser.	ch13 security cors
When do you need antiforgery (CSRF) protection?	When authentication is a cookie that the browser sends automatically. Bearer tokens in the <code>Authorization</code> header are not sent automatically. Add <code>SameSite</code> cookies as a second layer.	ch13 security csrf aspnetcore
Why must Data Protection keys be shared across replicas?	They encrypt auth cookies and antiforgery tokens. With per-pod keys, cookies fail on another pod or after restart. Persist keys to a shared store and set the same <code>SetApplicationName</code>.	ch13 security data-protection aspnetcore
Rules S7/S22: what is the DoS pattern and the fix?	Buffering whole request bodies (<code>EnableBuffering()</code> without limits, <code>CopyToAsync(MemoryStream)</code>). Fix: per-route size cap, 413, stream instead of buffering.	ch13 security dos aspnetcore
Why is <code>Request.ContentLength</code> alone not a body-size check?	It can be missing (chunked transfer). Also set <code>IHttpMaxRequestBodySizeFeature.MaxRequestBodySize</code> or <code>[RequestSizeLimit]</code>, which Kestrel enforces while reading.	ch13 security dos aspnetcore
Rule S21: why extract JWT bearer event handlers from <code>Program.cs</code>?	Long inline lambdas in auth config are untested and hard to review. A named <code>JwtBearerEvents</code> subclass (via <code>EventsType</code>) can have unit tests.	ch13 security authentication aspnetcore
What is wrong with using <code>JwtSecurityTokenHandler.ReadJwtToken</code> to get the user id?	It only parses. No signature, issuer, audience or expiry check, so anyone can create the token (Critical).	ch13 security authentication jwt
Five things a JWT validation configuration must check?	Issuer, audience, lifetime, signing key, allowed algorithms (<code>ValidAlgorithms</code>). Also a small <code>ClockSkew</code> (default is 5 minutes).	ch13 security authentication jwt
Rule S12: why is <code>Convert.FromBase64String(jwtPart)</code> a BLOCKER?	JWT parts are Base64URL (<code>-</code>, <code>_</code>, no padding). It fails only for some token contents, so some users fail and tests pass. Use <code>Base64UrlEncoder.Decode</code> or a token handler.	ch13 security authentication jwt
Why is deleting the cookie on logout not enough?	The token or session stays valid on the server. Logout must invalidate it server-side (<code>session-not-invalidated</code>).	ch13 security authentication
Three A09 logging checks in the Smartcat checklist?	<code>audit-missing</code> (high-value operation without audit entry), <code>pii-in-logs</code>, <code>exception-swallowed-silently</code>. All Warnings.	ch13 security logging smartcat
Rule S11: what may you log about an upstream HTTP failure?	Status code, duration, request id. Response bodies and user document content: Debug at most, behind an <code>IsEnabled(LogLevel.Debug)</code> guard.	ch13 security logging
Why is PII in logs a security problem even when the database is protected?	Logs have wider access, longer retention and may go to third parties. At Smartcat document text, TMs and glossaries are customer data.	ch13 security logging smartcat
What is SSRF and why is it dangerous inside a cluster?	The attacker makes your server request a URL they choose. The server can reach internal services, admin ports and the cloud metadata endpoint (169.254.169.254).	ch13 security ssrf
Five layers of SSRF defence?	1) Allow-list, https only. 2) Parse with <code>Uri</code>, reject user info. 3) <code>AllowAutoRedirect = false</code>. 4) Check the resolved IP at connect time. 5) Network egress rules. Plus size/time limits.	ch13 security ssrf
What is DNS rebinding in the SSRF context?	A time-of-check/time-of-use bug: the host resolves to a public IP at validation and to a private IP at connect time. Fix: check the IP inside <code>SocketsHttpHandler.ConnectCallback</code> and connect to that checked address.	ch13 security ssrf
Rule S10: why <code>IOptions&lt;T&gt;</code> instead of <code>IConfiguration</code> in business classes?	Typed, bound once in the module, testable, and typos are visible. Raw <code>IConfiguration</code> belongs only in bootstrap code (MINOR).	ch13 security secrets configuration
Rule S17: how should crypto/secret configuration be validated?	<code>AddOptions&lt;T&gt;().Bind(...).ValidateDataAnnotations().Validate(...).ValidateOnStart()</code>. Fail fast at startup, not inside a service method.	ch13 security secrets configuration
Why is <code>import.meta.env.VITE_API_KEY</code> a leak?	Vite inlines every <code>VITE_*</code> value into the public bundle (FS4). Secrets stay on the backend.	ch13 security secrets frontend
Rule FS1: when is <code>v-html</code> a BLOCKER?	When it renders LLM output, <code>marked(...)</code> output, HTTP responses or user input without <code>DOMPurify.sanitize</code> (shared helper with an allow-list).	ch13 security xss frontend
Why are tokens in <code>localStorage</code> a risk?	Any script on the page can read them; one XSS in any dependency exports the token. Prefer <code>httpOnly</code> cookies or memory only (and then add CSRF protection).	ch13 security xss frontend authentication
How do you find vulnerable NuGet packages, including transitive ones?	<code>dotnet list package --vulnerable --include-transitive</code>, and NuGet Audit on restore (<code>NuGetAuditMode=all</code>, NU1901&ndash;NU1904; fail CI on high/critical).	ch13 security supply-chain nuget
Review question for a <code>-beta</code> or <code>-preview</code> package in a production service?	Why is stable not enough, who owns the upgrade, and is there a plan? Pre-releases have no stability or security-fix promise.	ch13 security supply-chain nuget
What does Package Source Mapping prevent?	Dependency confusion: a public package with the same name as an internal one. Each package prefix maps to one feed.	ch13 security supply-chain nuget
Rule S15: why is dead code from merge conflicts a security rule?	Orphaned methods, unreachable branches and <code>*Old.cs</code>/<code>*Backup.cs</code> keep unreviewed logic in the binary; an old routed controller is an unwatched endpoint.	ch13 security supply-chain code-review
Fixed scan order for a security code review?	Identity &rarr; tenant &rarr; input to structure &rarr; output &rarr; secrets/crypto &rarr; logs/audit &rarr; resources. Style last.	ch13 security code-review interviewer
At Smartcat: what should a reviewer do with <code>.claude-review/past-incidents.md</code>?	Treat entries as repo-specific rules and cite the original MR/ticket when a finding matches. If absent, use only the canonical rules.	ch13 security code-review smartcat
Interviewer: which follow-up separates a Senior from a Staff answer on SSRF?	Ask what happens when DNS changes after the allow-list check. Staff answers with connect-time IP checks, no auto-redirect and egress policy; Senior often stops at the allow-list.	ch13 security ssrf interviewer
Interviewer: which follow-up separates a Senior from a Staff answer on tenant isolation?	&quot;How do you make sure a new developer cannot forget the filter?&quot; Staff proposes structure: a repository that always adds the tenant, a fail-closed context, convention and two-tenant tests.	ch13 security tenant-isolation interviewer
Interviewer: three red flags in a security review answer?	&quot;It is internal, so it is safe&quot;; &quot;GUIDs cannot be guessed&quot;; hashing passwords with SHA-256 or suggesting <code>DangerousAcceptAnyServerCertificateValidator</code> &quot;for now&quot;.	ch13 security interviewer
How do you test that no future write endpoint misses <code>[Authorize]</code>?	A convention test that scans controller actions with write verbs and asserts <code>[Authorize]</code> on the action or controller. It inspects attributes only, so it does not pin private state.	ch13 security access-control testing
