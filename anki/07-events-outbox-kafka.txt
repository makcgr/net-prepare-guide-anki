#deck:DotNet Interview Guide::07 Domain events, the Outbox pattern and Kafka
#tags column:3
What is the difference between a command and a domain event?	A command is a request (&quot;do this&quot;) with exactly one owner that can refuse it. An event is a fact in the past tense (&quot;this happened&quot;) with zero or many receivers.<br>The producer of an event does not know who listens.	ch07 events commands
Name three kinds of decoupling that events give you.	<ul><li>Logical: the producer does not know its consumers.</li><li>Temporal: the consumer can be down; events wait in Kafka.</li><li>Data: consumers build their own read models.</li></ul>	ch07 events decoupling
Notification event vs event-carried state transfer?	Notification: only ids, the consumer calls back for data (small, but extra load and a race).<br>State transfer: the event carries the data consumers need, so they can build read models without calls back.	ch07 events design
When is an event the wrong tool?	When the caller needs an answer now (use a query), when the caller must know the action failed (use a command or a task), or when you need a strong invariant across services at one moment.	ch07 events design
Why is <code>SendInvoiceEmailEvent</code> a bad event name?	It is a command in disguise: it has one expected receiver and the producer depends on it.<br>Name the fact instead (<code>InvoiceIssued</code>) and let the email service react.	ch07 events naming
What is the dual-write problem?	You must write to two systems (e.g. MongoDB and Kafka) that share no transaction. Any order of the two writes has a crash window that loses an event, publishes a phantom event, or duplicates it.	ch07 dual-write outbox
What goes wrong with &quot;save to Mongo, then publish to Kafka&quot;?	If the process dies after the save and before the publish, the data changed but the event is lost forever. A pod restart during deploy is enough.	ch07 dual-write
What goes wrong with &quot;publish to Kafka, then save to Mongo&quot;?	If the save fails, consumers react to a change that never happened (a phantom event).	ch07 dual-write
Why do Kafka transactions not solve the dual-write problem with MongoDB?	Kafka transactions cover Kafka writes and consumer offsets only. Your MongoDB write is outside them. 2PC between Mongo and Kafka is not available.	ch07 dual-write kafka transactions
Describe the Outbox pattern in two steps.	1. Store the event in the same atomic write as the state change.<br>2. A separate relay reads stored events, publishes them to Kafka, then removes them.	ch07 outbox
What delivery guarantee does an outbox relay give, and why?	At-least-once. The relay can crash after publishing and before removing the event; on restart it publishes again. So consumers must be idempotent.	ch07 outbox at-least-once
Name three alternatives or variants of the polling outbox.	Separate outbox collection/table written in a DB transaction; Change Data Capture (Debezium, Mongo change streams); &quot;listen to yourself&quot; (publish first, update own state in own consumer).	ch07 outbox cdc
At Smartcat, which base class must an entity inherit to use the embedded outbox?	<code>DomainEntity</code>. It holds <code>NewEvents</code> (stored in the <code>mqEvents</code> field) and provides <code>AddEvents(...)</code>.	ch07 smartcat outbox domainentity
Where should an entity call <code>AddEvents</code>?	In the same domain method that changes its state (e.g. <code>TryMarkDeleted</code>). Then the event cannot be forgotten and cannot be raised without the change.	ch07 smartcat outbox design
What is wrong with this update?<pre><code>Builders&lt;ProjectTask&gt;.Update<br>    .Set(t =&gt; t.Status, task.Status)<br>    .Set(t =&gt; t.NewEvents, task.NewEvents);</code></pre>	<code>Set</code> overwrites the events array with the in-memory copy. A concurrent writer's events are lost (or already published events come back).<br>Use <code>.PushEach(t =&gt; t.NewEvents, task.NewEvents)</code>.	ch07 smartcat outbox pusheach code-review
Why does <code>PushEach</code> keep both events when two writers update the same document?	<code>$push</code> with <code>$each</code> appends to the array value that is in the database at write time, atomically. Each writer adds only its own events.	ch07 smartcat outbox pusheach mongodb
PTS repositories warn: push the entity's own <code>NewEvents</code>, not a bare event object. Why?	<code>NewEvents</code> are wrapped stored events that carry the revision the outbox orders by. A bare object has no revision, the relay cannot read it, and the event is never delivered, with no error.	ch07 smartcat outbox
Which index does a Smartcat outbox collection need?	A partial index <code>{ &quot;mqEvents.rev&quot;: 1 }</code> with <code>partialFilterExpression: { &quot;mqEvents.rev&quot;: { $exists: true } }</code>.<br>The relay polls by it; at rest it is almost empty.	ch07 smartcat outbox indexes
What happens if a collection with an outbox has no <code>mqEvents.rev</code> index?	Every relay poll becomes a full collection scan, many times per second.	ch07 smartcat outbox indexes
How does the outbox relay find repositories to poll at Smartcat?	Through DI: each repository is registered as <code>IOutboxEventRepository</code> with a unique <code>Name</code> and a <code>GetEvents(limit)</code> method. Forget the registration and events are stored but never published.	ch07 smartcat outbox di
Embedded outbox vs <code>OutboxEventRepositoryV2</code> at Smartcat?	Embedded: events in the entity's <code>mqEvents</code> array, atomic via a single-document update with <code>PushEach</code>.<br>V2: events in a separate outbox collection, atomic via a Mongo transaction (<code>WithTransaction</code> + <code>AddEvents(session, ...)</code>).	ch07 smartcat outbox
What are the parameters of <code>[MqEvent(...)]</code>?	<code>discriminator</code>: stable unique event type name for routing.<br><code>orderGroupProperty</code>: property whose value is the Kafka key (ordering).<br><code>obsolete</code>: optional deprecation flag.	ch07 smartcat mqevent
Why is renaming an event's discriminator dangerous?	Consumers route by the discriminator string. After a rename they silently stop receiving the event; no test or exception tells you. PTS pins it with a contract test.	ch07 smartcat mqevent versioning
What does <code>EventWithIdempotencyKeyBase</code> give an event?	An automatically generated unique event id, used by idempotent handlers as the deduplication key.	ch07 smartcat idempotency
How do you choose the order key (<code>orderGroupProperty</code>)?	Use the smallest entity whose events must stay in order (e.g. assignment id, project id). Wider keys give more ordering but create hot keys and wider DLQ blocking.	ch07 kafka ordering design
What does Kafka guarantee about message order?	Order only inside one partition. The key decides the partition, so you get order per key. No order across keys, partitions or topics.	ch07 kafka ordering
What limits consumer parallelism in one Kafka consumer group?	The number of partitions. Each partition is read by one consumer of the group; extra pods stay idle.	ch07 kafka partitions scaling
Why is adding partitions to a topic not free?	The key-to-partition mapping changes (hash mod N), so order for existing keys can break during the change. Partitions also cannot easily be removed.	ch07 kafka partitions
What is a consumer offset and a commit?	The offset is the position in a partition. A commit saves it for the consumer group, so after a restart the group continues from there.	ch07 kafka offsets
At-most-once vs at-least-once: where is the commit?	At-most-once: commit before processing (a crash loses the message).<br>At-least-once: commit after processing (a crash re-delivers, so duplicates).	ch07 kafka delivery-semantics
What does Kafka &quot;exactly-once&quot; actually cover?	Kafka-to-Kafka processing with transactions (read, write, commit offsets atomically). Not database writes or HTTP calls. Real systems use at-least-once plus idempotency for an exactly-once effect.	ch07 kafka delivery-semantics
What triggers a consumer group rebalance?	A consumer joins or leaves (deploy, scale, crash), or a consumer misses <code>max.poll.interval</code> because its handler is too slow.	ch07 kafka rebalancing
Why does a slow handler cause duplicates?	It misses the poll interval, Kafka gives its partitions to another consumer, and the new owner re-processes messages whose offsets were not committed.	ch07 kafka rebalancing
Two services use the same Kafka <code>groupId</code> by mistake. What happens?	They split the messages between them instead of both receiving all messages. Each service misses part of the events.	ch07 kafka consumer-groups
Retention vs compaction in Kafka?	Retention keeps messages for a time or size limit, then deletes them. Compaction keeps only the latest message per key. Retention also defines how long a consumer can be down.	ch07 kafka retention
At Smartcat, what must match a handler's <code>MessageHandlerId Id</code>?	The ConsumerSet key in the Kafka config. Binding is at runtime; a mismatch builds fine and then fails with &quot;message handler X not found&quot;.	ch07 smartcat handlers consumerset
A Smartcat handler is registered but never called and no error appears. Name two likely causes.	The <code>IEventHandler&lt;T&gt;</code> is not registered in DI, or the event type is missing from the dispatcher's handled-types list. Neither is a compile or runtime error.	ch07 smartcat handlers
When should you use a batch handler (<code>IMessageBatchHandler</code>)?	For high-volume events: one DB round trip per batch and collapsing many updates of one entity. Cost: one bad message can fail the batch, and idempotency must work per item.	ch07 smartcat batch-handler
Why should a Kafka handler not do long work like file processing?	It exceeds the poll interval, causes rebalances and duplicates. Record the intent (create a background task) and return quickly.	ch07 kafka handlers design
List four sources of duplicate messages in an at-least-once system.	Relay crash after publish; consumer crash after effect but before commit; rebalance after a slow poll; manual DLQ replay.	ch07 idempotency at-least-once
Name four techniques for idempotent handlers.	Natural idempotency (<code>$set</code>, upsert); dedup store with unique (handler, eventId); version/timestamp check; unique business key with duplicate-key catch.	ch07 idempotency
How does <code>SingleEventWithIdempotencyKeyProcessorBase</code> work?	It looks up (handlerName, eventId) in a processed-events collection. If present, skip. If not, run <code>HandleUnprocessed</code> and insert the record in one Mongo transaction.	ch07 smartcat idempotency
Which indexes does a processed-events collection need?	Unique <code>{ eventId: 1, handlerName: 1 }</code> (<code>UDX_EventId_HandlerName</code>) and a TTL index on <code>{ expireTime: 1 }</code>.	ch07 smartcat idempotency indexes
In an idempotent Smartcat handler, which writes are protected by the dedup transaction?	Only writes made through the <code>IClientSessionHandle</code> passed to <code>HandleUnprocessed</code>. HTTP calls, emails and writes without the session are not.	ch07 smartcat idempotency transactions
How do you make an external side effect (email, payment) idempotent?	Pass the event id as an idempotency key to the external system, or turn the effect into a task with a unique key. The local dedup record alone does not cover it.	ch07 idempotency side-effects
What is the risk of the dedup record TTL?	A duplicate that arrives after the TTL (e.g. a DLQ replay after a long incident) is processed again. Choose TTL by the longest realistic replay window.	ch07 idempotency ttl
What is wrong with &quot;if not processed, process, then mark processed&quot; without a unique index?	It is a check-then-act race: two consumers (e.g. during a rebalance) both see &quot;not processed&quot; and both run.	ch07 idempotency race
How does <code>ComputedAt</code> in <code>ProjectTaskSummaryChanged</code> help consumers?	The consumer updates its read model only if the event is newer than what it holds. That makes it idempotent and safe against reordering.	ch07 smartcat idempotency ordering
Three classes of handler errors and what to do with each?	Validation (bad message): log and skip.<br>Transient (timeout, 503): retry with backoff and a budget, then DLQ.<br>Unknown/bug: DLQ with an alert to the owner.	ch07 errors retry dlq
Why must bad input not throw a generic exception in a Smartcat handler?	It goes to the DLQ and can never succeed, and it blocks all later messages of the same order key. Throw <code>ValidationException</code> so it is skipped.	ch07 smartcat errors dlq
How is the Smartcat DLQ keyed?	By (messageHandlerId, topicId, orderGroupKey). One DLQ per failing key, not one global queue.	ch07 smartcat dlq
A message for key K goes to the DLQ. What happens to the next message for K? For key L?	The next message for K is appended to K's DLQ (even if it would succeed), to keep order. Messages for L continue normally.	ch07 smartcat dlq ordering
Which Mongo collections hold the Smartcat DLQ?	<code>messageQueues.dlq.v2</code> (one DLQ task per handler+topic+key) and <code>messageQueues.dlq.v2.messages</code> (the queued messages with offsets).	ch07 smartcat dlq
Name the main fields of a Smartcat DLQ task.	<code>deadLetterQueueId</code> (messageHandlerId, topicId, orderGroupKey), <code>messageCount</code>, <code>reason</code> (first failure), <code>responsibleTeams</code>, <code>state</code>.	ch07 smartcat dlq
Query: all open Smartcat DLQs?	<pre><code>db["messageQueues.dlq.v2"].find({ "state": { "$ne": 2 } })</code></pre>	ch07 smartcat dlq monitoring
How must DLQ messages of one key be replayed?	In offset order (<code>sort({ &quot;message.offset&quot;: 1 })</code>), after the cause is fixed, with idempotent handlers.	ch07 smartcat dlq replay
Why do Smartcat handlers declare <code>ResponsibleTeams</code>?	The value goes into the DLQ record, so the alert reaches the team that can fix the code. A DLQ nobody watches is slow data loss.	ch07 smartcat dlq alerting
What is wrong with catching all exceptions in a handler and only logging them?	The message is lost silently: offset is committed, no DLQ, no alert, no replay.	ch07 errors code-review
Which changes to an event contract are safe?	Adding optional fields (consumers ignore unknown fields; new consumers handle null from old messages). Removing, renaming, changing types, or renaming the discriminator are breaking.	ch07 versioning contracts
How do you ship a breaking event contract change?	Expand and contract: add a new event/discriminator or optional fields, publish both, move consumers one by one, mark old <code>obsolete</code>, stop publishing after retention and DLQs drain.	ch07 versioning contracts
What is a tolerant reader?	A consumer that reads only the fields it needs, ignores unknown fields, and accepts missing optional fields.	ch07 versioning
Deploy order for an additive event field?	Consumers that can read the new field first, then the producer that writes it. Old messages remain without the field.	ch07 versioning deploy
What does a PTS contract test like <code>ProjectStatusChangedContractTests</code> check?	The discriminator is unchanged, and an old-shape payload still deserializes with old members equal and new members null.	ch07 smartcat testing contracts
What is a saga?	A long business process across services made of local transactions; on failure, earlier steps are undone by compensating actions, not by rollback.	ch07 saga
Choreography vs orchestration?	Choreography: services react to each other's events (loose coupling, hard to see the process).<br>Orchestration: a coordinator drives steps and tracks state (explicit, but a central dependency).	ch07 saga
Why must compensation distinguish user cancel from infrastructure failure?	User cancel: compensate and stop. Infra failure (pod died, lock lost): the user still wants the result, so resume or retry. Compensating on infra failure undoes wanted work (review rule A7).	ch07 saga compensation a7
What does review rule A34 require for a workflow started by a UI confirmation?	Pass an idempotency key from the confirmation id, so a double click or client retry does not start two workflows.	ch07 saga idempotency a34
What is review rule T14 for event/state code?	Replay-idempotency test: process the same input twice (same message id or idempotency key) and assert a single side effect.	ch07 testing t14 idempotency
What is review rule T17?	When code adds retry, add a test that simulates N+1 failures and asserts that the loop gives up (retry budget exceeded).	ch07 testing t17 retry
Why is review rule A22 relevant to events?	A loop of <code>UpdateOneAsync</code> calls for one domain operation is not atomic; events and state can disagree after a crash. Use one update, <code>UpdateMany</code> with array filters, or a transaction.	ch07 a22 atomicity outbox
Interviewer: which follow-up separates a Senior from a Staff answer on idempotent handlers?	Ask what the dedup transaction does NOT cover. Staff names external side effects, the TTL replay window, and rebalance races, and proposes idempotency keys or tasks.	ch07 interviewer idempotency
Interviewer: name three red flags in an events design answer.	&quot;Kafka is exactly-once so duplicates do not matter&quot;; publishing right after <code>Save</code> in the same <code>try</code>; &quot;catch all and log to keep the consumer alive&quot;.	ch07 interviewer
Interviewer: a good scenario to open an events interview?	&quot;We save an order and must notify billing. Walk me through it.&quot; Then add failures: pod dies, Kafka down, handler throws, duplicate, new contract.	ch07 interviewer
Interviewer: what probe tests understanding of order keys?	&quot;Your key is account id. What happens for a customer with 10 million tasks, and when one of its messages fails?&quot; (hot partition, whole account blocked in the DLQ).	ch07 interviewer ordering
Consumer lag grows for one handler. First checks?	Is the handler bound (ID mismatch, disabled)? DLQ growth or a poison message? Slow handler and rebalances? Pods vs partitions? Hot key?	ch07 kafka operations
