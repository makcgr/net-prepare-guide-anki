What is the main reason behind the test pyramid?	Tests cost time to run and time to diagnose. Fast, focused tests should be the majority; slow, wide tests should be few and check wiring that small tests cannot see.	ch10 test-pyramid
Which test level should check a MongoDB filter, and why not a unit test with a faked collection?	A repository test against a real (ephemeral or Docker) Mongo.<br>Faking <code>IMongoCollection&lt;T&gt;</code> only proves your code calls the driver, not that the query returns the right documents.	ch10 test-pyramid mongodb
At which level should a regression test for a production bug live?	At the lowest level that can reproduce the bug.<br>Lower level = faster, and the failure points closer to the cause.	ch10 test-pyramid regression
NUnit vs xUnit: how many fixture instances are created per test class by default?	NUnit: ONE instance shared by all tests in the fixture. xUnit: a new instance per test.<br>In NUnit, fields leak between tests unless <code>[SetUp]</code> resets them.	ch10 nunit lifecycle
How can you make NUnit create a new fixture instance per test?	<code>[FixtureLifeCycle(LifeCycle.InstancePerTestCase)]</code> (NUnit 3.13+).	ch10 nunit lifecycle
Order the NUnit lifecycle attributes and say how often each runs.	<code>[OneTimeSetUp]</code> once before all tests &rarr; <code>[SetUp]</code> before each test &rarr; test &rarr; <code>[TearDown]</code> after each test (also after failure) &rarr; <code>[OneTimeTearDown]</code> once after all.	ch10 nunit lifecycle
What is wrong with this NUnit fixture field?<pre><code>private readonly List&lt;int&gt; _items = new();</code></pre>(tests add items to it)	The fixture instance is shared by all tests, so the list keeps items from previous tests. Create it in <code>[SetUp]</code>.	ch10 nunit shared-state
<code>TestCase</code> vs <code>TestCaseSource</code>: when do you need the second?	<code>TestCase</code> accepts only compile-time constants. <code>TestCaseSource</code> takes objects, collections, records from a <b>static</b> member.	ch10 nunit parameterized
How do you give each <code>TestCaseSource</code> row a readable name?	<code>new TestCaseData(...).SetName(&quot;Should_...&quot;)</code> (or <code>TestName = ...</code> on <code>[TestCase]</code>).	ch10 nunit parameterized
<code>Assume.That</code> vs <code>Assert.That</code>?	<code>Assume.That</code> makes the test inconclusive (not failed) when false. Use it for preconditions in Arrange; <code>Assert.That</code> is for results.	ch10 nunit assume
What does <code>Assert.Multiple</code> give you?	It reports all failed asserts inside the block, not only the first one. Good for several fields of one result.	ch10 nunit assertions
Why is <code>ParallelScope.All</code> dangerous with default NUnit fixtures?	Tests of the same fixture run at the same time on ONE shared instance, so they write the same fields concurrently. Use it only without mutable fields or with <code>InstancePerTestCase</code>.	ch10 nunit parallel
Which parallel scope do PTS component fixtures use, and what does it mean?	<code>Parallelizable(ParallelScope.Fixtures)</code>: fixtures run in parallel; tests inside one fixture run one by one against one booted host.	ch10 nunit parallel smartcat
Why does PTS forbid classic NUnit asserts like <code>Assert.AreEqual</code>?	Analyzers reject them and <code>TreatWarningsAsErrors</code> turns that into a build failure. Only the constraint model (<code>Assert.That</code>) is allowed.	ch10 nunit assertions smartcat
Give two reasons the constraint model is better than classic asserts.	Actual always comes first (no swapped expected/actual); constraints compose (<code>Has.Count.EqualTo(3)</code>, <code>Is.Not.Null.And.Not.Empty</code>); better failure messages.	ch10 nunit assertions
Does <code>Assert.ThrowsAsync&lt;OperationCanceledException&gt;</code> pass when the code throws <code>TaskCanceledException</code>?	No. <code>Throws</code>/<code>ThrowsAsync</code> match the exact type. Use <code>Assert.CatchAsync&lt;T&gt;</code> or <code>Throws.InstanceOf&lt;T&gt;()</code> for subtypes.	ch10 nunit exceptions async
In the Smartcat monolith, how do you declare the delegate for <code>Assert.ThrowsAsync</code>?	<code>Func&lt;Task&gt; act = () =&gt; sut.RunAsync();</code> then <code>Assert.ThrowsAsync&lt;T&gt;(act)</code>.<br><code>AsyncTestDelegate</code> is obsolete there and CS0618 is an error.	ch10 nunit exceptions smartcat
Why must a test never be <code>async void</code>?	The runner cannot observe the result; exceptions can be lost and the test can pass or crash the run. Return <code>Task</code>.	ch10 async nunit
What does an unconfigured FakeItEasy fake return for: int, string, Task&lt;T&gt;, an interface?	Dummies: <code>0</code>, <code>&quot;&quot;</code>, a completed task with a dummy T, and another fake for the interface. NOT <code>null</code> for interfaces.	ch10 fakeiteasy
Why does a &quot;not found&quot; test often pass by accident with FakeItEasy?	The fake returns a dummy object, not <code>null</code>, so the code takes the happy path. Configure <code>.Returns((Document?)null)</code> explicitly.	ch10 fakeiteasy common-mistake
FakeItEasy: how do you return different values on consecutive calls?	<code>.ReturnsNextFromSequence(a, b, c)</code>; for computed values per call use <code>.ReturnsLazily(() =&gt; ...)</code>.	ch10 fakeiteasy
FakeItEasy: how do you make an async method fail?	<code>.ThrowsAsync(new TimeoutException())</code> (or <code>.Throws(...)</code> for sync members). For <code>Task&lt;T&gt;</code> success, <code>.Returns(value)</code> works directly.	ch10 fakeiteasy async
FakeItEasy: three ways to match an argument?	<code>A&lt;T&gt;._</code> / <code>A&lt;T&gt;.Ignored</code> (any), <code>A&lt;T&gt;.That.Matches(x =&gt; ...)</code> (condition), an exact value.	ch10 fakeiteasy
FakeItEasy: how do you capture the arguments of calls?	<code>.Invokes((Entity e) =&gt; saved.Add(e))</code>, then assert on <code>saved</code>. FakeItEasy 8+ also has <code>A.Captured&lt;T&gt;()</code>.	ch10 fakeiteasy capture
What is wrong with a test whose only assertion is <code>MustHaveHappenedOnceExactly()</code> (rule T5)?	It pins how the code works, not what it achieves. A valid refactoring breaks it. Assert the resulting state; verify calls only when the call is the behaviour.	ch10 fakeiteasy review-rules
When is call verification the right assertion?	When the call IS the contract: an event must be published, an external API must not be called when a flag is off, a lock must be taken before saving.	ch10 fakeiteasy verification
What do <code>AddFake&lt;T&gt;()</code>, <code>AddSingleton&lt;TService, TImpl&gt;()</code> and <code>Get&lt;T&gt;()</code> do in Smartcat <code>BaseTest</code>?	Register a fake and return it; register a real implementation; resolve the class under test with dependencies injected from the test container.	ch10 basetest smartcat
Why use a DI container in unit tests instead of <code>new Service(a, b, c)</code>?	A new constructor dependency does not break every test; the container supplies a fake. Tradeoff: wiring is less visible. For tiny pure classes <code>new</code> is still clearer.	ch10 basetest
Name the Smartcat test base classes and their use.	<code>BaseTest</code> (DI + fakes), <code>BaseEphemeralMongoTest</code> (in-process Mongo), <code>BaseMongoTest</code> (Docker Mongo), <code>BaseKafkaTest</code>, <code>BaseElasticsearchTest</code>. PTS adds <code>BaseDockerMongoFixtureTest</code>, <code>BaseComponentTest</code>.	ch10 basetest smartcat
What is the Smartcat test naming convention?	<code>Should_&lt;behaviour&gt;[_when_&lt;condition&gt;]</code>, underscores, lowercase after Should.<br>Example: <code>Should_increment_retry_count_when_processing_fails</code>.	ch10 naming smartcat
What AAA rules do monolith reviewers enforce?	Bare markers (<code>// Arrange</code>, no text after); blank lines between parts; one Act; preconditions as <code>Assume.That</code> in Arrange; Act is the awaited call.	ch10 aaa smartcat
Does &quot;one behaviour per test&quot; mean &quot;one Assert.That per test&quot;?	No. Several asserts that describe ONE result (fields of one state object) are fine; group them with <code>Assert.Multiple</code>. Two Acts usually mean two behaviours.	ch10 aaa
A test passes alone and fails in the full run. Top suspects?	Shared mutable state (static fields, fixture fields not reset), order dependence, parallel fixtures sharing a DB name or cache.	ch10 shared-state flaky
What is a seam, in testing?	A place where you can replace behaviour without editing the code under test, usually an injected interface at the process boundary (HTTP client, clock, publisher).	ch10 seams
What does the PTS rule say to mock, and what never?	Mock only seams: external services, time, randomness, I/O. Never the type under test or trivial value objects. Prefer real wiring when cheap (ephemeral Mongo).	ch10 seams smartcat
Why is faking an interface introduced in the same MR a MAJOR finding (T6)?	Both sides are new, so the fake only repeats the author&#39;s assumptions about it. The real interaction is never tested. Use the real implementation or an integration test.	ch10 seams review-rules
Why not assert on log messages (T10)?	Log text is not part of the contract. Such tests break on wording changes and do not prove behaviour.	ch10 review-rules
<code>BaseEphemeralMongoTest</code> vs Docker Mongo tests: when do you need Docker?	Ephemeral: fast, no Docker, basic queries. Docker/real server: transactions (replica set), index creation, migration tests.	ch10 mongodb
Why must PTS test Mongo be a replica set?	PTS uses transactions; a standalone <code>mongod</code> fails.	ch10 mongodb smartcat
What does <code>SC_TESTS_MONGO_CONNSTR</code> do in PTS tests?	Fixtures reuse that existing replica-set Mongo instead of starting a Testcontainers container. CI uses it (no Docker daemon there).	ch10 mongodb smartcat
Why use <code>pwsh ./scripts/run-tests.ps1</code> for PTS integration tests locally?	It starts ONE shared replica-set Mongo for all fixtures. Per-fixture containers race and give random <code>ReplicaSet Disconnected</code> failures.	ch10 mongodb smartcat running-tests
A PTS integration test fails with <code>Connection refused</code> on 27017 or <code>Exited (137)</code>. Code bug?	Probably not: these are infrastructure failures (Mongo not up, container OOM-killed). Check Docker / the shared Mongo first.	ch10 mongodb smartcat flaky
How do you test a new Mongo field with a legacy fallback (T2/T13)?	Insert raw BSON in the OLD shape (field missing), read it with the new code, assert the fallback value. Also test update propagating the new field.	ch10 mongodb review-rules
Why test null vs missing vs zero separately in Mongo (T4)?	They are three states. <code>Eq(field, 0)</code> does not match a missing field; <code>Eq(field, null)</code> matches both null and missing.	ch10 mongodb review-rules
In a test project, what does <code>WebApplicationFactory&lt;Program&gt;</code> give you?	Boots the real app in memory with <code>TestServer</code>: real middleware, routing, model binding, DI, no network port. <code>CreateClient()</code> returns an <code>HttpClient</code> to it.	ch10 integration aspnetcore
How do you replace an external dependency in a <code>WebApplicationFactory</code> test?	<code>WithWebHostBuilder(b =&gt; b.ConfigureTestServices(s =&gt; { s.RemoveAll&lt;IPaymentApi&gt;(); s.AddSingleton(fake); }))</code>.	ch10 integration aspnetcore
Why boot the test host in <code>[OneTimeSetUp]</code>, and what does it require from tests?	Booting takes seconds; share it per fixture. Tests must use unique data (new IDs) so they do not see each other&#39;s documents.	ch10 integration
What is real and what is fake in PTS <code>BaseComponentTest</code>?	Real: the service&#39;s modules (Web + Processing) and Mongo. Fake: monolith API client, Scol client, feature flags client. No Kafka broker needed.	ch10 integration smartcat
Which .NET type replaces <code>DateTime.UtcNow</code> for testable time, and what is its fake?	<code>TimeProvider</code> (.NET 8+). Fake: <code>FakeTimeProvider</code> from <code>Microsoft.Extensions.TimeProvider.Testing</code>; move time with <code>Advance</code>.	ch10 time
What else does <code>FakeTimeProvider.Advance</code> drive besides <code>GetUtcNow</code>?	Timers created from the provider, <code>Task.Delay(delay, provider)</code>, <code>WaitAsync(timeout, provider, ct)</code>. A 30-second retry test runs in milliseconds.	ch10 time async
Why prefer <code>Task.WaitAsync(timeout, TimeProvider, ct)</code> in Smartcat monolith product code?	Tests can drive the timeout with <code>FakeTimeProvider.Advance</code> instead of sleeping real seconds.	ch10 time smartcat
When do you need an injected ID provider instead of <code>Guid.NewGuid()</code>?	When the value matters (sorting, dedup or idempotency keys). If it does not matter, read the ID back from the result or capture it.	ch10 ids
What is wrong here?<pre><code>_ = worker.StartAsync();<br>await Task.Delay(500);<br>Assert.That(store.Items, Has.Count.EqualTo(1));</code></pre>	It hopes 500 ms is enough: slow and still flaky. Wait for a signal (a <code>TaskCompletionSource</code> set from the fake), with a timeout only as a safety net.	ch10 async flaky
Why create test <code>TaskCompletionSource</code> with <code>RunContinuationsAsynchronously</code>?	Otherwise continuations run inline inside <code>TrySetResult</code> on the caller&#39;s thread, causing surprising re-entrancy or deadlocks.	ch10 async concurrency
How do you test a lock deterministically (T3)?	Deliberate contention: many calls via <code>Task.WhenAll</code>, a gate (TCS) that holds the first caller inside the section, an <code>Interlocked</code> counter of max concurrency; assert max is 1. No sleeps.	ch10 concurrency review-rules
What is a replay test (T14)?	Run the same input twice (same message ID / idempotency key) and assert exactly one side effect. Needed because Kafka delivers at least once.	ch10 idempotency review-rules
What does T17 require for new retry code?	A test with N+1 induced failures that asserts the loop gives up (budget exceeded), so a bug cannot become an infinite retry.	ch10 retry review-rules
Why is <code>string.GetHashCode()</code> unsafe for persisted or cross-pod state (T18)?	It is randomized per process in .NET Core, so two pods compute different hashes. Use a stable hash (XxHash64, SHA-256 over UTF-8 bytes).	ch10 hashing review-rules
What is a characterization test?	A test that pins what legacy code does TODAY, without judging it, so you have a green baseline before changing it.	ch10 legacy characterization
How do you quickly write a characterization test?	Assert a value you know is wrong, run it, read the real value from the failure message, paste it in. Now it is green and pins current behaviour.	ch10 legacy characterization
What does the PTS rule say before modifying existing behaviour?	Characterization first: never edit production code that has no test covering the behaviour you are about to change.	ch10 legacy smartcat
How do you check that a regression test is valid (T11)?	Revert the production fix locally and run it: it must be red. A test that passes without the fix proves nothing.	ch10 regression review-rules
What makes a valid RED in TDD?	The test fails on an assertion mismatch for the expected reason, not a compile error, missing type or typo.	ch10 tdd
When is a TDD opt-out acceptable, and how is it recorded?	Config-only change, rename, docs, generated files, dependency bump. State it: &quot;no meaningful test: reason&quot;. Never write a fake test to satisfy the gate.	ch10 tdd
Which reflection patterns are forbidden in tests?	<code>GetField</code>/<code>GetProperty</code>/<code>GetMethod</code> with <code>BindingFlags.NonPublic</code> + GetValue/SetValue/Invoke; <code>Activator.CreateInstance</code> / <code>Assembly.GetType(&quot;...&quot;)</code> on internal types by name; <code>[UnsafeAccessor]</code> for the same.	ch10 reflection smartcat
Why is reading a private field via reflection in a test harmful?	It pins the implementation; a rename breaks at runtime, not compile time; find-usages and rename refactorings miss the string. It usually hides a missing dependency.	ch10 reflection
Fix order for a test that needs non-public members?	1) Assert observable behaviour via the public API. 2) Extract the hidden piece into its own type / injected dependency. 3) Only then <code>internal</code> + <code>InternalsVisibleTo</code>.	ch10 reflection smartcat
Review severity for reflection into non-public members?	MINOR by default; MAJOR when the test project already has <code>InternalsVisibleTo</code> on the assembly under test (option 3 was a one-word change).	ch10 reflection smartcat interviewer
Which reflection in tests IS allowed?	Architecture tests that only inspect structure (scan types, inheritance, attributes, forbidden overrides); and one shared helper for third-party internals with no public API, commented.	ch10 reflection
Why does <code>dotnet test src/Tests/Tests.csproj</code> fail with <code>MSB4019</code> in Smartcat repos?	Test projects import <code>$(SolutionDir)\.build\TestProject.props</code>; a bare csproj build leaves <code>SolutionDir</code> empty. Target the <code>.sln</code> or pass <code>-p:SolutionDir=&lt;root&gt;/</code>.	ch10 running-tests smartcat
Why can <code>dotnet test X.sln --filter Foo</code> run the whole suite?	Under the MTP runner bridge the top-level <code>--filter</code> is silently ignored. Use <code>dotnet test X.sln -- --filter &quot;Foo&quot;</code> and check the executed count.	ch10 running-tests mtp
How do you select NUnit <code>[Category(&quot;Integration&quot;)]</code> in a filter?	<code>TestCategory=Integration</code> (not <code>Category=</code>). Exclude: <code>TestCategory!=Integration</code>.	ch10 running-tests
Where does the MTP opt-in live in Smartcat repos?	In the shared <code>.build/TestProject.props</code> (<code>EnableNUnitRunner</code>, <code>OutputType=Exe</code>, <code>TestingPlatformDotnetTestSupport</code>), not in the csproj.	ch10 running-tests mtp smartcat
How do you run FDA tests, given <code>dotnet test</code> discovers zero tests?	Build the test project, then <code>dotnet vstest &quot;.../Smartcat.FdaService.Tests.dll&quot; --TestCaseFilter:&quot;FullyQualifiedName~X&quot;</code>.	ch10 running-tests smartcat
How do you run monolith tests in a fresh git worktree?	Run the full <code>pwsh ./buildBackend.ps1</code> once (a scoped build misses MTP runner DLLs), then run the DLL directly: <code>dotnet buildResult/app/bin/X.Tests.dll --filter &quot;...&quot;</code>.	ch10 running-tests smartcat
What is the recommended run cadence for backend tests?	Filtered class while editing; everything except integration after a larger change; a full unfiltered run before calling the task done.	ch10 running-tests
Interviewer: what probe separates Senior from Staff on test design?	Ask how they would make a whole module testable. Senior fakes at seams; Staff designs the seams (time, IDs, external clients) so every risk has a cheap test level, and removes whole classes of flaky tests.	ch10 interviewer
Interviewer: name three red flags in a candidate&#39;s testing answer.	&quot;100% coverage&quot; as the goal; mocking the class under test or the Mongo driver; <code>Thread.Sleep</code> in tests; reflection into private fields as normal practice.	ch10 interviewer
Interviewer: a good follow-up after a candidate writes a happy-path test?	&quot;Your fake returns an entity for any ID. Which branch is now untested?&quot; It checks if they configure negative paths (null, throws, cancellation).	ch10 interviewer fakeiteasy
