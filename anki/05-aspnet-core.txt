What does the generic host (<code>IHost</code>) own in an ASP.NET Core app?	Configuration, the DI container, logging, and application lifetime.<br>The web server (Kestrel) is just one hosted service the host runs.	ch05 hosting generic-host
What is the hard line that <code>builder.Build()</code> draws in a <code>WebApplication</code> app?	Before it you register services; after it the container is read-only and you configure the pipeline.<br>You cannot add services after Build().	ch05 hosting webapplication
Why is calling <code>builder.Services.BuildServiceProvider()</code> in Program.cs a bug?	It builds a second DI container. Its singletons are different instances from the real app's.<br>Analyzer ASP0000 warns. Use builder.Configuration or app.Services after Build() instead.	ch05 hosting di
Why do services behind a Kubernetes ingress need <code>UseForwardedHeaders()</code>?	The proxy terminates TLS and forwards the request. Without it, <code>Request.Scheme</code> and the client IP are the proxy's values, not the real client's.	ch05 hosting kestrel proxy
Give the recommended middleware order for an API (exception handler to endpoints).	ExceptionHandler → HSTS → HttpsRedirection → Routing → CORS → Authentication → Authorization → RateLimiter/OutputCache/custom → endpoints.	ch05 pipeline middleware-order
Why must <code>UseAuthentication</code> come before <code>UseAuthorization</code>?	Authorization reads <code>HttpContext.User</code>. Authentication builds it. In the wrong order User is anonymous and every [Authorize] fails.	ch05 pipeline auth middleware-order
Why must <code>UseCors</code> run before authorization?	Browser preflight <code>OPTIONS</code> requests carry no credentials. If auth runs first, the preflight gets 401 and the browser blocks the real call.	ch05 pipeline cors middleware-order
Why must <code>UseRouting</code> come before CORS and authorization?	Routing selects the endpoint and stores it on HttpContext. CORS and authorization read endpoint metadata (policies, [Authorize]). Without routing first, they see no endpoint.	ch05 pipeline routing middleware-order
Why is <code>UseExceptionHandler</code> registered first?	Middleware wraps the ones after it. Only the outermost position catches exceptions from all later middleware and the endpoint.	ch05 pipeline exceptions middleware-order
What is wrong with this convention-based middleware?<pre><code>public AuditMiddleware(RequestDelegate next, IUnitOfWork unitOfWork)<br>{ ... }   // IUnitOfWork is scoped</code></pre>	Convention-based middleware is created once for the app. A scoped dependency in its constructor is captured forever (captive dependency).<br>Fix: take it as an <code>InvokeAsync</code> parameter, or use <code>IMiddleware</code>.	ch05 middleware di captive-dependency
Convention-based middleware vs <code>IMiddleware</code>: key differences?	Convention: one instance, no DI registration, scoped services only via InvokeAsync parameters.<br>IMiddleware: resolved from DI per request, must be registered, constructor injection of scoped services is safe.	ch05 middleware compare
A route constraint like <code>{id:guid}</code> fails. What status code does the client get, and why?	404. Constraints are for matching, not validation. No endpoint matches, so routing returns not found. Validate format separately if you need 400.	ch05 routing constraints
Controllers vs minimal APIs: name the main tradeoffs.	Controllers: full MVC filter pipeline, familiar structure, mature client generation.<br>Minimal APIs: less ceremony and overhead, better Native AOT support, endpoint filters, route groups.<br>Both use the same routing and middleware.	ch05 minimal-api controllers compare
Why use <code>TypedResults</code> and <code>Results&lt;T1, T2&gt;</code> in minimal APIs?	They put response types into the signature, so OpenAPI can describe them and the compiler checks them. Plain IResult hides the schema.	ch05 minimal-api openapi
Give the order of MVC filter types in the pipeline.	Authorization → Resource → (model binding) → Action → action method → Exception (on error) → Result → result execution.	ch05 filters pipeline
What exceptions do MVC exception filters NOT catch?	Exceptions during result execution and exceptions in middleware. They cover controller creation, model binding, action filters and the action.<br>Use middleware / IExceptionHandler for global handling.	ch05 filters exceptions
How do you give a filter constructor dependencies when you apply it as an attribute?	<code>[ServiceFilter(typeof(T))]</code> (T registered in DI), <code>[TypeFilter(typeof(T))]</code>, or an attribute implementing <code>IFilterFactory</code>.<br>Plain attributes cannot use constructor injection.	ch05 filters di
Why does this transaction filter use <code>ExceptionDispatchInfo.Throw</code>?<pre><code>var executed = await next();<br>if (executed.Exception != null)<br>    ExceptionDispatchInfo.Throw(executed.Exception);</code></pre>	To rethrow the action's exception so the transaction aborts, while keeping the original stack trace. <code>throw executed.Exception</code> would reset it.	ch05 filters exceptions smartcat
What does <code>[ApiController]</code> give you?	Automatic 400 with ValidationProblemDetails when ModelState is invalid; binding source inference ([FromBody] for complex types); attribute routing required; problem details for error status codes.	ch05 validation apicontroller
How do you use FluentValidation in modern ASP.NET Core?	Register validators and call <code>IValidator&lt;T&gt;.ValidateAsync</code> explicitly (or from a filter), then return ValidationProblem. The old auto-validation integration package is deprecated.	ch05 validation fluentvalidation
What is wrong with this request DTO for an update endpoint?<pre><code>public sealed class UpdateTaskRequest<br>{<br>    public Guid UpdatedByUserId { get; init; }<br>}</code></pre>	Actor identity comes from the caller. Anyone can claim to be anyone. Take it from the authenticated <code>User</code> (review rule S20).	ch05 validation security s20
What is a captive dependency and why is it dangerous?	A longer-lived service holds a shorter-lived one (e.g. singleton holds scoped). The first request's instance is kept forever, so later requests see its user/tenant/culture. Compiles, passes unit tests, fails under real traffic. Review rule A1 (BLOCKER).	ch05 di captive-dependency a1
How do you detect captive dependencies before production?	<code>ValidateScopes</code> and <code>ValidateOnBuild</code> (on by default in Development; enable in tests via UseDefaultServiceProvider). Error: &quot;Cannot consume scoped service from singleton&quot;.	ch05 di captive-dependency
Why is <code>IHttpContextAccessor</code> in a singleton used by background workers a bug?	Background threads have no HTTP request, so HttpContext is null (or wrong). It is one of the A1 patterns.	ch05 di httpcontext a1
Why is injecting <code>IServiceProvider</code> into business classes a smell (A16)?	Service locator: hides dependencies, fails at call time instead of at startup validation, harder to test, hides lifetime bugs.<br>Allowed in composition root, factories and hosted service startup.	ch05 di service-locator a16
How should a <code>BackgroundService</code> use scoped services?	Inject <code>IServiceScopeFactory</code> and create one scope per unit of work:<pre><code>await using var scope = _scopeFactory.CreateAsyncScope();<br>var repo = scope.ServiceProvider.GetRequiredService&lt;IOutboxRepository&gt;();</code></pre>	ch05 di background-service
What are keyed services (.NET 8) and how do you consume one?	Several implementations of one interface registered under keys: <code>AddKeyedSingleton&lt;IStorage, S3Storage&gt;("s3")</code>. Consume with <code>[FromKeyedServices("s3")]</code> or <code>GetRequiredKeyedService&lt;T&gt;(key)</code>.	ch05 di keyed-services
Two registrations of <code>IClock</code> exist. What does <code>GetService&lt;IClock&gt;()</code> return, and what does <code>IEnumerable&lt;IClock&gt;</code> return?	GetService returns the last registration. IEnumerable returns all, in registration order.	ch05 di registration-order
<code>TryAddSingleton</code> vs <code>TryAddEnumerable</code>?	TryAddSingleton: adds only if the service type has no registration (lets apps override library defaults).<br>TryAddEnumerable: adds only if this exact implementation is not in the list yet (no duplicates in plugin lists).	ch05 di tryadd
Default configuration provider order for WebApplication.CreateBuilder?	appsettings.json → appsettings.{Environment}.json → user secrets (Development) → environment variables → command line. Later wins.	ch05 configuration layering
Base config has an array of 3 servers; an override file has 1. How many servers does the app see?	3. Arrays are indexed keys (Servers:0, :1, :2). The override replaces only index 0; indexes 1 and 2 stay from the base file.	ch05 configuration layering gotcha
<code>IOptions</code> vs <code>IOptionsSnapshot</code> vs <code>IOptionsMonitor</code>?	IOptions: singleton, never reloads.<br>IOptionsSnapshot: scoped, recomputed per request, supports named options.<br>IOptionsMonitor: singleton, CurrentValue reflects changes, OnChange callback.	ch05 options compare
Why can't you inject <code>IOptionsSnapshot&lt;T&gt;</code> into a singleton?	It is scoped. A singleton would capture it (captive dependency); scope validation rejects it.	ch05 options di captive-dependency
What does <code>ValidateOnStart()</code> do and why use it?	Runs options validation when the host starts instead of on first access. Bad config fails the deploy, not the first customer request. Review rule S17 requires it for secrets/crypto config.	ch05 options validation s17
What does review rule S10 say about <code>IConfiguration</code>?	Business classes take typed <code>IOptions&lt;TConfig&gt;</code>, not raw IConfiguration. Raw config hides needed keys, has no types and cannot be validated at startup.	ch05 options configuration s10
A singleton reads <code>options.Value</code> in its constructor. Operators change the value. What happens?	Nothing, IOptions never reloads. For live changes use IOptionsMonitor and read CurrentValue at the point of use.	ch05 options reload
What is wrong with this log call?<pre><code>_logger.LogInformation($"Project {projectId} exported");</code></pre>	String interpolation: no structured fields, a unique message per call, allocation even when the level is disabled (CA2254).<br>Use a template: <code>LogInformation("Project {ProjectId} exported", projectId)</code>.	ch05 logging structured
Why use the <code>[LoggerMessage]</code> source generator?	Generated code checks IsEnabled first, avoids boxing and params arrays, and gives stable EventIds. Use it on hot paths.	ch05 logging performance
What does review rule S11 forbid in logs?	PII and content: response bodies, document text, emails, tokens, TM segments at Information or higher. Log status codes, durations and ids.	ch05 logging security s11
Why is <code>new HttpClient()</code> per request (with using) a problem?	Socket exhaustion: each disposal closes the connection, which stays in TIME_WAIT. Under load the host runs out of ephemeral ports.	ch05 httpclient socket-exhaustion
Why is one static HttpClient forever also a problem, and how do you fix it without the factory?	Connections live forever, so DNS changes are never seen. Fix: <code>new SocketsHttpHandler { PooledConnectionLifetime = TimeSpan.FromMinutes(2) }</code>.	ch05 httpclient dns
How does <code>IHttpClientFactory</code> fix both socket exhaustion and stale DNS?	It pools HttpMessageHandlers (the expensive part) and rotates them after a lifetime (default 2 minutes). HttpClient objects are cheap wrappers around pooled handlers.	ch05 httpclient factory
Why must you not inject a typed HttpClient into a singleton?	Typed clients are transient. A singleton captures one instance and its handler forever, losing handler rotation (stale DNS). Inject IHttpClientFactory instead.	ch05 httpclient di captive-dependency
What does <code>AddStandardResilienceHandler()</code> add?	Rate limiter, total timeout, retry with exponential backoff and jitter, circuit breaker, per-attempt timeout (Microsoft.Extensions.Http.Resilience, Polly v8).	ch05 httpclient resilience
Which outbound calls are safe to retry automatically?	Idempotent ones (GET, PUT with full state, DELETE) or calls with an idempotency key. A retried non-idempotent POST can duplicate the effect (e.g. charge twice).	ch05 httpclient resilience idempotency
Which errors should a circuit breaker count (review rule A30)?	Infrastructure failures: 5xx, timeouts, network errors. Not user errors (4xx, parse errors), or bad input from one user can open the breaker for everyone.	ch05 httpclient resilience a30
401 vs 403?	401: not authenticated (missing/invalid credentials), with WWW-Authenticate.<br>403: authenticated but not allowed.	ch05 auth status-codes
What does a fallback authorization policy do?	Applies to endpoints with no authorization metadata. With <code>RequireAuthenticatedUser()</code> it makes the app secure by default; <code>[AllowAnonymous]</code> opts out.	ch05 auth authorization policies
What does review rule S20 require (BLOCKER)?	<code>[Authorize]</code> (action, controller or fallback policy) on every POST/PUT/PATCH/DELETE, and actor identity from the authenticated principal, never from the request body.	ch05 auth security s20
What does review rule S21 say about JWT bearer events?	Do not write long inline lambdas in <code>JwtBearerEvents</code> inside Program.cs/Server.cs. Extract a named class (e.g. via <code>options.EventsType</code>) with testable methods.	ch05 auth jwt s21
When do you use resource-based authorization?	When the decision needs the loaded entity (e.g. project belongs to the caller's workspace): <code>IAuthorizationService.AuthorizeAsync(User, resource, policy)</code>.	ch05 auth authorization
Describe graceful shutdown of an ASP.NET Core app on SIGTERM.	ApplicationStopping fires → Kestrel stops accepting and drains in-flight requests → hosted services StopAsync (reverse order) → stoppingToken cancelled → host waits up to ShutdownTimeout (30 s default) → exit.	ch05 hosted-services shutdown
What happens by default (.NET 6+) when <code>ExecuteAsync</code> throws an unhandled exception?	The host stops (<code>BackgroundServiceExceptionBehavior.StopHost</code>). Before .NET 6 the service died silently.	ch05 hosted-services exceptions
Why is an in-memory BackgroundService loop a poor fit for durable business jobs?	No persisted retry state, no distribution across pods, work lost on restart or SIGKILL. Use a durable queue/task framework (at Smartcat: task processing, chapter 08).	ch05 hosted-services smartcat
Liveness vs readiness checks?	Liveness failing restarts the pod: keep it cheap, no dependencies.<br>Readiness failing removes the pod from load balancing without restart: dependency checks belong here.	ch05 health-checks kubernetes
Default Kestrel max request body size?	30,000,000 bytes (about 28.6 MB). Change per endpoint with <code>[RequestSizeLimit]</code> or <code>IHttpMaxRequestBodySizeFeature</code>.	ch05 request-size kestrel
What does review rule S7 require for middleware that buffers the body?	Check <code>ContentLength</code> against a per-route cap before <code>EnableBuffering</code>/reading, and reject with 413.	ch05 request-size security s7
What is wrong with this upload code (S22)?<pre><code>var ms = new MemoryStream();<br>await Request.Body.CopyToAsync(ms, ct);<br>await _storage.SaveAsync(ms.ToArray(), ct);</code></pre>	The whole upload is held in memory (twice with ToArray). Parallel large uploads cause OOM. Stream <code>Request.Body</code> to storage and cap the size per route.	ch05 request-size security s22
Output caching vs response caching?	Response caching: follows HTTP Cache-Control headers, client can bypass, no invalidation.<br>Output caching (.NET 7+): server policies, tag eviction, request coalescing, Redis store in .NET 8.	ch05 caching compare
What does output caching NOT cache by default, and why?	Non-GET/HEAD, non-200, authenticated requests, and responses that set cookies. It prevents serving one user's data to another.	ch05 caching security
What two facts about the rate limiting middleware do weak answers miss?	The default rejection status is 503, so set 429. Limits are per process: 4 pods means 4 times the limit; cluster-wide limits need a shared store or the gateway.	ch05 rate-limiting
How do you implement global exception handling in .NET 8?	<code>AddProblemDetails()</code> + <code>AddExceptionHandler&lt;T&gt;()</code> (T : IExceptionHandler) + <code>UseExceptionHandler()</code>. Handlers run in registration order; <code>TryHandleAsync</code> returns false to pass to the next.	ch05 exceptions problem-details
Why must the global handler never return <code>exception.ToString()</code> in Production?	It leaks stack traces, internal paths, library versions and sometimes data. Return problem details with a trace id; log the details.	ch05 exceptions security
Which API changes are breaking for consumers?	Removing or renaming a field, changing type or meaning, making an optional field required, changing status codes. Adding optional fields is safe.	ch05 api-versioning compatibility
What does <code>WebApplicationFactory&lt;Program&gt;</code> give you?	The real app booted in memory with TestServer: routing, binding, filters, middleware, serialization and auth are all tested. Override services with <code>ConfigureTestServices</code>.	ch05 testing webapplicationfactory
Why does reading <code>Request.Body</code> synchronously throw in Kestrel?	<code>AllowSynchronousIO</code> is false by default: sync I/O blocks thread-pool threads and causes starvation under load. Use async reads; do not turn the flag on.	ch05 performance async
At Smartcat: what does a service's Program.cs do besides starting the server?	Parses command-line verbs: <code>RunOptions</code> runs the server, <code>MigrateOptions</code> runs database migrations, from the same binary.	ch05 smartcat hosting
At Smartcat: what replaces WebApplication.CreateBuilder and pipeline setup?	<code>StandardHostBuilder</code> (Smartcat.AppPlatform): UseLogger, UseForwardedHeaders, ConfigureGlobalRequestLogger, ConfigureServices, ConfigureApplication, ConfigureObservability, ConfigureHealthChecks, ConfigureApiClients.	ch05 smartcat hosting
At Smartcat: what are app roles?	Web, Processing (plus SignalR, Admin, ClientPortal in the monolith). One binary, deployed as several Helm instance groups with different roles, so HTTP and background load scale separately.	ch05 smartcat app-roles
At Smartcat: how does a module register a controller?	A <code>ServiceProviderModule</code> overrides <code>Load(IServiceCollection, IConfiguration)</code> and calls <code>AddController&lt;TController&gt;()</code>. The module must load in Modules.cs for the Web role.	ch05 smartcat modules
At Smartcat: your new endpoint returns 404 locally. What do you check first?	That the controller is registered with AddController&lt;T&gt;() in a module that Modules.cs loads for the Web role (likely required for exposure). Then route template and constraints.	ch05 smartcat modules routing
At Smartcat: how is a settings class defined and registered?	Implements <code>IConfig</code> with a static <code>SectionName</code> and in-code defaults; registered with <code>services.AddConfigOptions&lt;T&gt;()</code> in a settings module; consumed as options.	ch05 smartcat options
At Smartcat: give the .configurations load order.	common.json → {ENV_GROUP}/common.json → {ENV_GROUP}/{ENV_NAME}/... → namespace folder → SMARTCAT_CONFIG_PATHS files → development/override.dev.json (git-ignored, dev only). Later wins.	ch05 smartcat configuration layering
At Smartcat: what is the role of .configurations/common.json?	The schema: every key the service uses with environment-independent defaults and no real credentials. Environment files override only what differs.	ch05 smartcat configuration
At Smartcat: how do you call another Smartcat service?	Reference its <code>Smartcat.{Service}.ApiClient</code> NuGet, add <code>.Configure{Service}Client()</code> to the HttpClientSettingsBuilder chain, add the <code>{Service}Api</code> section (url, timeout, maxRetryCount). Never raw HttpClient.	ch05 smartcat httpclient api-client
At Smartcat: why is AllowAnyOrigin CORS in smartcat-ai-agents not automatically a vulnerability?	Likely because auth uses an explicit header token, not cookies, so a foreign origin cannot send credentials automatically. With cookie auth it would be a serious finding.	ch05 smartcat cors security
At Smartcat: why is the scheduling MCP server registered with <code>Stateless = true</code>?	With several replicas, a stateful MCP session pinned to one pod breaks round-robin load balancing (follow-up calls hit a pod without the session → 404).	ch05 smartcat multi-pod
Interviewer: what follow-up separates a Senior from a Staff answer on DI lifetimes?	Ask &quot;where else does per-request state leak?&quot;. Senior finds captive dependencies. Staff also covers background threads (no HttpContext), AsyncLocal, per-pod caches, and how to enforce detection (ValidateOnBuild in tests, review rule).	ch05 interviewer di
Interviewer: a good scenario question for HttpClient and resilience?	&quot;A partner service became slow; our pods stop answering.&quot; Listen for: timeouts, thread-pool starvation from sync waits, retry storms, circuit breakers, cancellation propagation, bulkheads.	ch05 interviewer httpclient
Interviewer: red flags in an ASP.NET Core interview?	&quot;Make everything singleton&quot;; new HttpClient in a using; catch-all returning 200 with an error flag; userId from the body; no idea what ValidateOnStart or stoppingToken are for.	ch05 interviewer red-flags
