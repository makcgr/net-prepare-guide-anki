Which source wins when the repo <code>.editorconfig</code> and the general .NET guidelines disagree?	The repo <code>.editorconfig</code> (and the prevailing pattern in the file).<br>Tooling and reviewers enforce it; consistency in one codebase is worth more than one rule being &quot;right&quot;.	ch02 style editorconfig
At Smartcat (monolith, PTS), how are private methods named?	camelCase: <code>private void processDocument()</code>.<br>Why: visibility is visible at the call site, so you know a change stays inside the class.	ch02 naming smartcat
Does smartcat-ai-agents also use camelCase private methods?	No. Its <code>.editorconfig</code> uses PascalCase for all methods (rule D20 flags camelCase private static methods).<br>Lesson: check each repo's <code>.editorconfig</code>.	ch02 naming smartcat
How are private fields, private constants and private static readonly fields named at Smartcat?	<code>_camelCase</code>: <code>_documentService</code>, <code>_maxRetry</code>, <code>_retention</code>.<br>Rule D13 flags <code>private const int MaxRetries</code>.	ch02 naming smartcat
How should abbreviations be cased in identifiers? Example: LQA errors.	Like a normal word: <code>LqaError</code>, <code>_lqaErrors</code>, not <code>LQAError</code>.<br>Word boundaries stay readable and the camelCase form is obvious.	ch02 naming
What namespace pattern do new Smartcat projects use?	<code>Smartcat.{Solution}.{Project}.{Folder}</code>, e.g. <code>Smartcat.ImageService.Module.Services</code>.<br>Old monolith code uses <code>AbbyyLS.SmartCAT.*</code>; do not rename it.	ch02 naming smartcat
Folder and class naming rule: <code>Service/Things.cs</code> or <code>Services/ThingService.cs</code>?	<code>Services/ThingService.cs</code>: plural folder, singular class.<br>A folder is a collection, a class is one thing.	ch02 naming smartcat
What is wrong with this lambda?<pre><code>projectCosts.Sum(_ =&gt; _.Amount)</code></pre>	<code>_</code> means &quot;discard&quot; but the parameter is used.<br>Fix: <code>projectCosts.Sum(cost =&gt; cost.Amount)</code>. Use <code>_</code> only when the parameter is ignored.	ch02 naming lambdas
Rule D21: when is a single-letter lambda parameter not OK?	In a non-trivial lambda (2+ line body that touches several members).<br>Use a name that matches the type: <code>agent =&gt; ...</code>. <code>x =&gt; x.Id</code> is fine.	ch02 naming lambdas
Rule D4: what must classes named Mapper, Builder and Factory do?	Mapper: pure <code>Map(Source) -&gt; Target</code>, no side effects.<br>Builder: mutable config, then <code>Build()</code> returns X.<br>Factory: parameter-driven creation.	ch02 naming review-rules
Rule D22: a method <code>TryAuthenticate</code> returns an access token. What is the problem?	The name says &quot;verify identity&quot; but it fetches a token.<br>Name what it returns: <code>TryResolveAccessTokenAsync</code>.	ch02 naming review-rules
Rules D17/D19: what is the naming rule for one concept inside a file?	One term per concept (<code>Tag</code> vs <code>Code</code>, <code>Account</code> vs <code>Workspace</code>).<br>Mixed terms make readers ask if there are two different things.	ch02 naming review-rules smartcat
At Smartcat, what is the Account vs Workspace terminology drift?	The monolith historically calls a workspace an &quot;account&quot; (<code>AccountId</code>); newer APIs say Workspace.<br>In new code follow the surrounding new code; do not mix both for one boundary.	ch02 naming smartcat
Rule D24: tool output records all have <code>Id</code> and <code>Name</code>. Fix?	Prefix fields with the domain: <code>CustomTemplateId</code>, <code>CustomTemplateName</code>.<br>The consumer (often an LLM) cannot tell bare fields from different tools apart.	ch02 naming review-rules
How should an enum be named? Give the sentence test.	Suffix Status/Type/Mode/State/Style, never <code>Enum</code>.<br>&quot;Name + is + value&quot; forms a sentence: &quot;Document status is Draft&quot;.	ch02 enums
What is wrong here?<pre><code>[Flags]<br>public enum DocumentOptions<br>{<br>    ReadOnly = 1,<br>    Hidden = 2,<br>    ReadOnlyAndHidden = 3<br>}</code></pre>	Missing <code>None = 0</code> and the combination uses a literal.<br>Use <code>ReadOnlyAndHidden = ReadOnly | Hidden</code> so renumbering cannot break it silently.	ch02 enums
In what order should enum members be declared?	Alphabetical or semantic (lifecycle order: Draft, Processing, Completed, Failed). Never random.	ch02 enums
Rule A8: classes <code>RunningStatus</code>, <code>ActiveStatus</code> with no fields. What to do?	Use an enum <code>RunStatus { Running, Active, Pending }</code> and put behavior in a service.<br>Empty status classes are an enum in disguise.	ch02 enums review-rules
Write the Smartcat MongoDB model pattern for a mandatory Guid field <code>AccountId</code>.	<pre><code>[BsonElement("accountId"), BsonRequired]<br>public required Guid AccountId { get; init; }</code></pre>	ch02 mongodb smartcat
Why does every Mongo field get an explicit <code>[BsonElement(&quot;camelCase&quot;)]</code>?	It decouples the C# name from the stored name, so a property rename is safe.<br>It also prevents casing mismatches between model, migrations and indexes.	ch02 mongodb smartcat
Why use <code>required</code> + <code>init</code> on Mongo models?	<code>required</code>: the compiler forces every creator to set mandatory fields.<br><code>init</code>: immutable after creation; changes go through explicit update methods.	ch02 mongodb
What do <code>[BsonRequired]</code> and <code>[BsonIgnoreIfDefault]</code> do in the model pattern?	<code>BsonRequired</code>: deserialization fails loudly if a mandatory field is missing.<br><code>BsonIgnoreIfDefault</code>/<code>BsonIgnoreIfNull</code>: optional fields are not written when empty.	ch02 mongodb
Why store enums as strings in MongoDB (<code>[BsonRepresentation(BsonType.String)]</code>)?	Int storage changes meaning silently if someone reorders or inserts a value.<br>Also: readable raw data in incidents, and external tools can query it. Cost: a few bytes.	ch02 mongodb enums smartcat
A migration creates an index on <code>&quot;AccountId&quot;</code>; the model stores <code>&quot;accountId&quot;</code>. What happens?	The index is created and valid but no query uses it (field names are case-sensitive).<br>A known review BLOCKER: PascalCase migration vs camelCase model.	ch02 mongodb indexes
Rule D16: what is flagged on a Mongo-mapped class, and the fix?	Public <code>{ get; set; }</code> properties (MINOR).<br>Fix: <code>public required X Foo { get; init; }</code> and factory/update methods for changes.	ch02 mongodb review-rules
You see a Mongo model with a constructor, <code>private set</code> and a private parameterless ctor. Should you rewrite it to <code>required</code> + <code>init</code>?	Not without a reason. It is the older pattern with the same goal (no accidental mutation).<br>Use the new pattern for new models; do not churn old ones in unrelated MRs.	ch02 mongodb smartcat
A Guid <code>Eq</code> filter finds nothing, but a tool shows the document. First suspect?	Guid binary representation mismatch (legacy subtype 3 vs standard subtype 4).<br>Keep the representation the collection already uses.	ch02 mongodb guid
Why separate DB entity, API request and API response types?	Security: no mass assignment of fields like <code>AccountId</code>.<br>Change independence: internal fields do not leak into the contract.<br>Different shapes: BSON attributes vs serializer-friendly DTO.	ch02 models
What is the Smartcat DTO / contract pattern?	No constructors, public setters, no attributes, sensible defaults:<br><code>public string Name { get; set; } = string.Empty;</code><br>Serializers and generated clients work best with it.	ch02 models smartcat
A published contract uses <code>[DataMember(Name = ...)]</code>. Casing rule?	camelCase, matching the JSON field name. A wrong casing is a contract break (review warning).	ch02 models smartcat
What is the Smartcat config class pattern?	<pre><code>internal sealed class MyServiceConfig<br>{<br>    public required string ConnectionString { get; init; }<br>    public int Timeout { get; init; } = 30;<br>}</code></pre>Required keys, immutable after bind, defaults in code.	ch02 config smartcat
Does <code>required</code> on an options class guarantee a startup failure if the key is missing?	Not by itself: the configuration binder works by reflection and may not enforce it.<br>Add <code>ValidateOnStart()</code>/data annotations or a module check.	ch02 config
What index name prefixes does Smartcat use?	<code>UDX_</code> unique, <code>IDX_</code> non-unique, with fields in order: <code>UDX_AccountId_Name</code>, <code>IDX_State_UpTime</code>. TTL indexes seen as <code>IDX_UpdatedAt_TTL</code>.	ch02 indexes smartcat
Why must you keep existing <code>IX_</code> index names?	An index is identified by name: rename = drop + create.<br>Long build on big collections, primary load, a window without the index, for zero value.	ch02 indexes smartcat
Why put the field list into the index name?	Field order in a compound index matters (equality, sort, range). The name lets a reviewer check it in <code>explain()</code> output without opening the definition.	ch02 indexes
Smartcat member ordering inside a class?	public, internal, protected (each: const, fields, methods, properties), then private methods and properties, then private const and fields at the very end.	ch02 ordering smartcat
Why does Smartcat put private fields at the bottom of the class?	A reader opens a class for its public contract; private fields are implementation detail.<br>(Many .NET codebases put fields first; match the file.)	ch02 ordering smartcat
Constructor vs <code>required</code> + <code>init</code>: when to use each?	Constructor: invariants to check, validation, derived values.<br><code>required</code> + <code>init</code>: data carriers with many fields and no logic (models, configs, events).	ch02 constructors
Why prefer <code>Rename(name)</code> over a public <code>Name</code> setter on a domain object?	A method names the business action, can check rules and is searchable.<br>A setter can be called from anywhere with no check.	ch02 constructors
Is <code>required</code> enforced at runtime by every deserializer?	No. It is a compile-time check for initializers. System.Text.Json honors it (.NET 7+); the Mongo driver does not, so add <code>[BsonRequired]</code>.	ch02 constructors mongodb
Monolith: how do you use nullable reference types in a new file?	Add <code>#nullable enable</code> at the top. Nullable is not global in the monolith.<br>In an old file, wrap only your block with <code>#nullable enable</code> ... <code>#nullable restore</code>.	ch02 nullable smartcat
Why not enable nullable for a whole old file inside a feature MR?	A 5-line change becomes 200 warnings and an unreviewable diff. Enable it module by module in separate MRs.	ch02 nullable
What is the risk of many <code>!</code> (null-forgiving) operators?	Each <code>!</code> claims &quot;I know better than the compiler&quot;. Used to silence warnings, it hides real null bugs. Use it only with a reason.	ch02 nullable
What does <code>TreatWarningsAsErrors=true</code> buy you?	Warning count stays at zero, so every new warning (e.g. possible null dereference) is visible. Cost: SDK/analyzer upgrades can break the build.	ch02 tooling
Rule D12: indentation in Smartcat C# files? How to fix wrong files?	Tabs per <code>.editorconfig</code>. Fix: <code>dotnet format whitespace --include &lt;file&gt;</code>. Monolith max line width: 120.	ch02 tooling smartcat
Rule D5: what is wrong with injecting <code>IConfiguration</code> into a business class?	Hard to test, keys spread across classes, no startup validation, hidden dependency.<br>Fix: options class + <code>services.Configure</code>/<code>AddOptions().BindConfiguration()</code> + <code>IOptions&lt;T&gt;</code>.	ch02 config review-rules
Where is <code>IConfiguration</code> allowed under rule D5?	In composition code: <code>Module.cs</code> (<code>Load(services, configuration)</code>), <code>Startup.cs</code>, <code>Program.cs</code>.	ch02 config review-rules smartcat
<code>IOptions&lt;T&gt;</code> vs <code>IOptionsSnapshot&lt;T&gt;</code> vs <code>IOptionsMonitor&lt;T&gt;</code>?	IOptions: singleton, read once. Snapshot: scoped, re-read per request. Monitor: singleton with change notifications.<br>Snapshot cannot be injected into a singleton.	ch02 config
Rule D15: what does it flag?	Task-returning methods without the <code>Async</code> suffix, and <code>Async</code>-suffixed methods that do not return a task.<br>Enforced in smartcat-ai-agents.	ch02 async naming review-rules
Does PTS use the <code>Async</code> suffix?	Almost never: the PTS module has ~0 public Task methods with it (e.g. <code>Upsert</code>, <code>Get</code>). smartcat-ai-agents uses it widely. Follow the repo.	ch02 async naming smartcat
What is wrong here?<pre><code>try { Check(x); return true; }<br>catch { return false; }</code></pre>	Rule D8 (MAJOR): exception as success indicator.<br>Expensive stack traces, bare catch hides real failures, monitoring noise. Use <code>bool TryX(out T)</code> or <code>Result&lt;T&gt;</code>.	ch02 exceptions review-rules
When is catching an exception and returning false acceptable?	At a boundary with a third-party API that only signals by exceptions: catch a specific type and log. Never bare catch inside your own domain.	ch02 exceptions
Rule D6 (MAJOR): what is the risk of mutable objects across <code>await</code>?	After await, code may run on another thread with other requests in between; a shared mutable object becomes a race.<br>Fix: <code>sealed record</code> + <code>with</code>, or local state.	ch02 async review-rules
Rule D1: which numbers are exempt from the magic-number rule?	<code>0</code>, <code>1</code>, <code>-1</code>, size hints and test data. Others with business meaning get a named constant.	ch02 magic-numbers review-rules
Why prefer <code>TimeSpan.FromSeconds(5)</code> over <code>_retryDelayMs = 5000</code>?	The unit is in the type, no arithmetic for the reader, no ms/s confusion. Rule A38 asks named durations (or options) for TTLs and leases.	ch02 magic-numbers
Rule D7: how do you fix 3+ levels of nested if?	Guard clauses (early returns), extract a method, or a strategy if branches differ by type.	ch02 readability review-rules
Rule D9: simplify <code>items.Where(p).Count() &gt; 0</code>.	<code>items.Any(p)</code>. Also <code>Where(p).Any()</code> -&gt; <code>Any(p)</code>. A repeated predicate -&gt; an extension method.	ch02 linq review-rules
Mongo filters: simplify <code>Builders&lt;T&gt;.Filter.And(a, b)</code>.	<code>a &amp; b</code> (and <code>a | b</code> for Or). Same result, shorter (a NIT rule).	ch02 mongodb review-rules
What is Smartcat's comment policy for production code?	Code is self-descriptive: no inline comments unless needed (non-obvious invariant, external-bug workaround). <code>///</code> doc comments 1–2 lines on public/non-obvious members.	ch02 comments smartcat
Smartcat formatting rule for one-line comments?	No dot at the end: <code>// Keeps the old name for compatibility</code>. English only.	ch02 comments smartcat
Rule D26: <code>// will be improved later</code>. Fix?	Link a ticket (<code>// TODO(DEV-12345): ...</code>) or delete it. A promise without a ticket is never kept.	ch02 comments review-rules
Rule A39: which fields need a longer contract comment?	TTL/lease fields (<code>expiresAt</code>, <code>lockedUntil</code>): who writes, who cleans up, worst staleness window, crash behavior.	ch02 comments review-rules
Why are stale comments considered worse than no comments?	The compiler checks code, nobody checks comments. Readers trust a wrong comment. Long reasoning belongs in the MR description.	ch02 comments
When is a local function justified at Smartcat?	Only when it significantly simplifies the code (e.g. eager argument validation for an iterator or async method). &quot;Only used here&quot; is not enough.	ch02 local-functions smartcat
Rule D2 (MAJOR): what is dead code from merge resolution?	New unreferenced methods/classes, <code>*Old.cs</code>, <code>*Backup.cs</code>, <code>*V2.cs</code> files, &quot;legacy from branch&quot; comments. It looks alive and gets maintained.	ch02 review-rules
Rule D11: a production project pins <code>Foo 2.0.0-rc1</code>. Severity?	BLOCKER: pre-release NuGet in production. Exception: <code>Microsoft.Agents.AI</code> (pre-1.0 by design) is MINOR.	ch02 nuget review-rules
Rule D27: the MR title says &quot;bump X to 3.1&quot; but the diff has no version change. Severity and fix?	BLOCKER. Fix the diff or the title/description. Ship reality, not intent.	ch02 review-rules
Rule D10: what must be in English in config?	File names, keys and comments under <code>.configurations/</code> and <code>.helmchart/</code>. Values may be any language.	ch02 config review-rules
Interviewer: what signal separates a Staff answer on &quot;enums as strings&quot; from a Senior one?	Senior explains reorder risk. Staff adds the rollout: existing int data needs a dual-read serializer or a migration before switching.	ch02 interviewer
Interviewer: red flag in a style-review exercise?	Spends minutes on spacing and misses the shared DB/API model or exception-as-success; or proposes renaming existing indexes.	ch02 interviewer
Interviewer: good opening task for a style interview?	A 30–40 line class mixing a get/set Mongo model used as API response, an int enum, try/catch return false, a magic 5000, raw IConfiguration. Ask for findings ordered by importance.	ch02 interviewer
