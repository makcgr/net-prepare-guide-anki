What does <code>await</code> do when the awaited task is not complete yet?	It registers the rest of the method as a continuation and returns an incomplete task to the caller. The thread goes back to the pool (or the UI loop).<br>When the operation completes, the continuation runs on the captured context, or on a pool thread if there is none.	ch03 async await-basics
Does <code>await</code> create a new thread?	No. It only releases the current thread while the operation is pending. During true async I/O no thread is waiting at all.<br>Code that is CPU-bound inside an async method still runs on the caller thread.	ch03 async await-basics
Until which point does an async method run synchronously?	Until the first <code>await</code> of an operation that is not yet complete. If every awaited operation is already complete, the whole method runs synchronously.	ch03 async state-machine
What does the C# compiler generate for an <code>async</code> method?	A state machine type (a struct in Release, a class in Debug) implementing <code>IAsyncStateMachine</code>: a <code>MoveNext()</code> with the original body, a state field, hoisted locals, and a method builder (<code>AsyncTaskMethodBuilder</code>) that creates and completes the returned task.	ch03 async state-machine
When is the async state machine moved to the heap?	Only at the first real suspension (an await of an incomplete operation). The synchronous fast path stays on the stack and allocates nothing extra.	ch03 async state-machine performance
What members must a type have to be awaitable (the awaiter pattern)?	An accessible <code>GetAwaiter()</code> (instance or extension) that returns an awaiter with <code>bool IsCompleted</code>, <code>OnCompleted(Action)</code> (INotifyCompletion, optionally UnsafeOnCompleted) and <code>GetResult()</code>.<br>It is pattern-based, like <code>foreach</code>.	ch03 async awaiter
Where does an exception thrown inside an <code>async Task</code> method go?	It is caught by the generated code and stored in the returned task. The caller sees it only when it awaits the task (or reads <code>.Result</code>).<br>So argument checks inside an async method fail at the await, not at the call.	ch03 async exceptions
What is wrong with this code?<br><pre><code>public Task&lt;string&gt; DownloadAsync(Uri uri)<br>{<br>    using var client = new HttpClient();<br>    return client.GetStringAsync(uri);<br>}</code></pre>	The await is elided, so <code>client</code> is disposed when the method returns, while the request is still running.<br>Fix: make it <code>async</code> and <code>return await</code>. Elide only in one-line pass-throughs with no using/try.	ch03 async eliding
Name three behavior differences between <code>return task;</code> and <code>return await task;</code>.	<ul><li>using/try around the call: elided version disposes too early</li><li>synchronous exceptions of the callee: thrown at the call site vs stored in the task</li><li>stack trace: method missing vs present</li></ul>Also: no state machine when elided.	ch03 async eliding
What problem does <code>ValueTask&lt;T&gt;</code> solve?	It avoids a heap allocation when the result is often available synchronously (cache hit, buffered read). It holds a result, a <code>Task&lt;T&gt;</code>, or a pooled <code>IValueTaskSource&lt;T&gt;</code>.	ch03 async valuetask
What are the rules for consuming a <code>ValueTask</code>?	<ul><li>Await it only once</li><li>Never await it concurrently</li><li>No <code>.Result</code> / <code>GetResult()</code> before it completes</li><li>Otherwise call <code>.AsTask()</code> once and use the Task</li></ul>Why: a pooled source is reused after GetResult.	ch03 async valuetask
Task vs ValueTask: which one is the default for a new async API?	<code>Task</code>. Use <code>ValueTask</code> only for measured hot paths where synchronous completion is common. ValueTask adds rules and size with no gain when the method usually completes asynchronously.	ch03 async valuetask
What is wrong here?<br><pre><code>var t = GetSettingsAsync(); // returns ValueTask&lt;Settings&gt;<br>await Task.WhenAll(t.AsTask(), other);<br>var settings = await t;</code></pre>	The ValueTask is consumed twice (<code>.AsTask()</code> and <code>await t</code>). With a pooled source the second await is undefined behavior.<br>Fix: <code>var t = GetSettingsAsync().AsTask();</code> and use only the Task.	ch03 async valuetask
What does await capture, and in which order does it check?	First <code>SynchronizationContext.Current</code>; if null, <code>TaskScheduler.Current</code> if it is not the default. The continuation is posted there. Otherwise it runs on the thread pool.	ch03 async synchronizationcontext
Does ASP.NET Core have a SynchronizationContext?	No. Continuations run on any pool thread. Legacy ASP.NET (System.Web), WPF, WinForms and MAUI do have one.	ch03 async synchronizationcontext aspnetcore
What does <code>ConfigureAwait(false)</code> do?	It tells the awaiter not to capture the context: the continuation runs on the thread pool. It prevents context deadlocks when someone blocks on your code and avoids an extra hop.	ch03 async configureawait
Should library code use <code>ConfigureAwait(false)</code> even though ASP.NET Core has no context?	Yes, on every await. A library does not control its host: a WPF tool or a legacy service may call it. In ASP.NET Core application code it has no practical effect; follow the file convention.	ch03 async configureawait
Why is <code>ConfigureAwait(false)</code> on only the first await not enough?	If the first awaited task is already complete, there is no suspension, so the method is still on the original context at the next await. Every await must have it.	ch03 async configureawait
Is <code>HttpContext</code> safe to use after <code>ConfigureAwait(false)</code> in ASP.NET Core?	Yes, it is not bound to a thread. But it is not thread-safe: never use it from two parallel tasks at once. It is also invalid after the request ends.	ch03 async configureawait aspnetcore
What does <code>ConfigureAwaitOptions.SuppressThrowing</code> (.NET 8) do, and where is it not allowed?	It waits for the task without throwing its exception (best-effort cleanup). It is allowed only on non-generic <code>Task</code>; on <code>Task&lt;T&gt;</code> it throws ArgumentOutOfRangeException.	ch03 async configureawait dotnet8
Explain the classic sync-over-async deadlock in one sentence.	A context thread blocks on <code>.Result</code>/<code>.Wait()</code>, the awaited method's continuation is posted to the same context, and it can never run because that thread is blocked.	ch03 async deadlock
Does <code>.Result</code> deadlock in ASP.NET Core? What happens instead?	No deadlock (no context), but thread-pool starvation under load: each blocked request holds a thread and needs another for the continuation, the pool grows slowly, the queue grows, latency explodes.	ch03 async deadlock starvation aspnetcore
<code>.Wait()</code> vs <code>.Result</code> vs <code>.GetAwaiter().GetResult()</code>: what differs?	All three block the thread. The first two throw <code>AggregateException</code>; <code>GetAwaiter().GetResult()</code> throws the original exception. None of them is safer against deadlock.	ch03 async deadlock
What is the &quot;async over sync&quot; anti-pattern?	A library method like <code>Task&lt;T&gt; ReadAsync() =&gt; Task.Run(() =&gt; Read())</code>: it looks async but blocks a pool thread on sync I/O. Expose the sync method and let the caller decide.	ch03 async task-run
Where is <code>async void</code> acceptable?	Only in event handlers. Otherwise the caller cannot await it, cannot catch its exceptions, and an exception with no context crashes the process.	ch03 async async-void
What is wrong here?<br><pre><code>projects.ForEach(async p =&gt; await _indexer.IndexAsync(p, ct));</code></pre>	<code>List.ForEach</code> takes <code>Action&lt;T&gt;</code>, so the lambda is <code>async void</code>. ForEach returns before indexing finishes, and an exception crashes the process.<br>Fix: <code>foreach</code> with <code>await</code>, or <code>Parallel.ForEachAsync</code>.	ch03 async async-void
Why is <code>Parallel.ForEach(items, async item =&gt; ...)</code> a bug?	The sync <code>Parallel.ForEach</code> takes <code>Action&lt;T&gt;</code>, so the lambda is async void: the loop ends at the first await of each body, and exceptions are not observed. Use <code>Parallel.ForEachAsync</code>.	ch03 async async-void parallel
Name four problems of <code>_ = DoWorkAsync();</code> in a controller.	<ul><li>Exceptions are unobserved and lost</li><li>The request DI scope is disposed: ObjectDisposedException</li><li>Work is lost on restart or deploy</li><li>No cancellation, no backpressure</li></ul>	ch03 async fire-and-forget
What happens to an unobserved task exception in modern .NET?	It does not crash the process (since .NET 4.5). It raises <code>TaskScheduler.UnobservedTaskException</code> when the task is garbage-collected, which is late and usually not logged.	ch03 async fire-and-forget exceptions
Alternatives to fire-and-forget background work, from light to strong?	<ul><li>Just await it</li><li><code>Channel&lt;T&gt;</code> + <code>BackgroundService</code> with a new DI scope per item</li><li>A persisted task (retry, survives restarts)</li><li>A domain event through the Outbox</li></ul>	ch03 async fire-and-forget
At Smartcat, where does background work that must not be lost go?	Into a persisted task of the task processing framework (Ordinary, Singleton or Sticky), captured by one pod at a time and retried, or into an Outbox event. Not a <code>Task.Run</code> from a controller.	ch03 async fire-and-forget smartcat
What does <code>await Task.WhenAll(a, b)</code> throw if both a and b fail?	Only the first exception. All of them are in <code>whenAllTask.Exception.InnerExceptions</code> (an AggregateException). Keep a reference to the WhenAll task to read them.	ch03 async exceptions whenall
When one task in <code>Task.WhenAll</code> fails, do the others stop?	No. They keep running; WhenAll completes only when all complete. To stop them, share a CancellationTokenSource and cancel it on the first failure.	ch03 async whenall cancellation
A task ended with OperationCanceledException. Which state is it in, and what should you catch?	State <code>Canceled</code>, not <code>Faulted</code>. Catch <code>OperationCanceledException</code> (the base type of TaskCanceledException), and do not log it as an error when the caller asked for it.	ch03 async cancellation exceptions
Who can cancel, and who observes, in .NET cooperative cancellation?	A <code>CancellationTokenSource</code> owns the right to cancel. A <code>CancellationToken</code> is the read-only view passed down; code checks it or passes it to APIs that check it. Nothing can force a method to stop.	ch03 async cancellation
In ASP.NET Core, what is a <code>CancellationToken</code> action parameter bound to?	<code>HttpContext.RequestAborted</code>, which fires when the client disconnects. Pass it to every I/O call.	ch03 async cancellation aspnetcore
Why must a linked CancellationTokenSource be disposed?	It registers a callback on the parent token. Without <code>Dispose</code> the registration lives as long as the parent, a leak for long-lived tokens. A CTS with CancelAfter also holds a timer.	ch03 async cancellation
How do you tell a timeout from a caller cancellation?	<pre><code>catch (OperationCanceledException) when (!callerToken.IsCancellationRequested)<br>{<br>    throw new TimeoutException(...);<br>}</code></pre>If the caller token is not cancelled, the linked timeout fired.	ch03 async cancellation timeout
When should you deliberately pass <code>CancellationToken.None</code> instead of the request token?	For work that must finish even if the client leaves: cleanup, releasing a lock, after-commit steps, or a shared lookup that several callers wait on. Add a comment that says why.	ch03 async cancellation
On which thread do callbacks registered on a token run when <code>Cancel()</code> is called?	Synchronously, on the thread that calls <code>Cancel()</code>. A slow or throwing callback affects the caller of Cancel.	ch03 async cancellation
Smartcat rule A7: what does it flag about cancellation?	One compensation handler for both user cancel and infrastructure failure (lost worker, shutdown) in background runs. Fix: distinct exception types or a CancellationReason on the run record. MAJOR.	ch03 async cancellation smartcat review
Does <code>task.WaitAsync(timeout)</code> cancel the original operation?	No. It only stops waiting. The original keeps running and may still write data. Cancel through a token when the operation supports it.	ch03 async timeout waitasync
Name three .NET 8 APIs that accept a <code>TimeProvider</code>.	<code>Task.WaitAsync(TimeSpan, TimeProvider, ct)</code>, <code>Task.Delay(TimeSpan, TimeProvider, ct)</code>, <code>new CancellationTokenSource(TimeSpan, TimeProvider)</code>. Also <code>timeProvider.GetUtcNow()</code> and <code>CreateTimer</code>.	ch03 async timeprovider
How do you test a 30-second timeout without waiting 30 seconds?	Inject <code>TimeProvider</code>; in the test use <code>FakeTimeProvider</code> (Microsoft.Extensions.TimeProvider.Testing) and call <code>Advance(TimeSpan.FromSeconds(31))</code>. Control the dependency with a TaskCompletionSource.	ch03 async timeprovider testing
Smartcat rule T8: what does it flag?	<code>DateTime.UtcNow</code> / <code>Guid.NewGuid()</code> inside non-test classes without an injected clock or id provider, and time-related asserts without a frozen clock. MINOR.	ch03 async timeprovider smartcat review
Why is <code>await Task.Delay(100)</code> in a test a smell?	It is slow and flaky on a busy CI agent: the background work may need longer. Use a fake clock or a TaskCompletionSource signal instead.	ch03 async testing
How do you run three independent reads concurrently?	<pre><code>var users = _users.GetAsync(id, ct);<br>var projects = _projects.GetAsync(id, ct);<br>await Task.WhenAll(users, projects);<br>var (u, p) = (users.Result, projects.Result); // completed</code></pre>Total time is the slowest call, not the sum.	ch03 async whenall
Smartcat rule A20: is <code>Task.WhenAll</code> over 500 single-document reads a fix?	Usually no. It is still 500 round trips. The fix for N+1 reads is one query: collect ids, <code>FindByIdsAsync(ids)</code>, join in memory.	ch03 async whenall smartcat review
What does <code>Task.WhenAny</code> return, and what must you do after it?	The first task that completed (success, fault or cancel). It never throws itself. Await the returned task to get its result or exception, and cancel the losers.	ch03 async whenany
What does <code>Task.WhenEach</code> (.NET 9) do?	Returns an <code>IAsyncEnumerable&lt;Task&lt;T&gt;&gt;</code> that yields tasks in completion order. It replaces the O(n&#178;) loop with WhenAny and Remove.	ch03 async wheneach dotnet9
Why throttle async fan-out?	Async makes starting 10 000 operations easy, but the database, downstream service and socket pool cannot take it. Throttling keeps the concurrency at what the dependency accepts.	ch03 async throttling
Write the SemaphoreSlim throttle pattern.	<pre><code>await _throttle.WaitAsync(ct);<br>try<br>{<br>    await DoWorkAsync(item, ct);<br>}<br>finally<br>{<br>    _throttle.Release();<br>}</code></pre>Release in finally, or a failure leaks a slot forever.	ch03 async throttling semaphoreslim
What is the default <code>MaxDegreeOfParallelism</code> of <code>Parallel.ForEachAsync</code>, and why set it for I/O?	<code>Environment.ProcessorCount</code>. That is a CPU number; for I/O set it to what the downstream system can take.	ch03 async throttling parallel
What does <code>Parallel.ForEachAsync</code> do on the first exception?	Stops taking new items, cancels the token passed to the running bodies, waits for them, and throws. Catch inside the body if you want to collect all failures.	ch03 async throttling parallel
Why is the result collection in <code>Parallel.ForEachAsync</code> a <code>ConcurrentBag</code> in PTS code, not a <code>List</code>?	Bodies run in parallel. <code>List&lt;T&gt;.Add</code> is not thread-safe and corrupts the list under concurrent writes. Use a concurrent collection or Interlocked for counters.	ch03 async throttling smartcat
What is <code>[EnumeratorCancellation]</code> for?	It marks the token parameter of an async iterator that receives the token from <code>WithCancellation(ct)</code> / <code>GetAsyncEnumerator(ct)</code>. Without it that token is ignored (warning CS8425).	ch03 async iasyncenumerable
When does the body of an async iterator start running?	At the first <code>MoveNextAsync()</code>, not when the method is called. Validation inside it runs late.	ch03 async iasyncenumerable
What happens if you <code>break</code> out of <code>await foreach</code>?	The compiler calls <code>DisposeAsync</code> on the enumerator, which runs the iterator's finally blocks (disposing cursors etc.). It is safe.	ch03 async iasyncenumerable
Why is <code>ToListAsync()</code> on a large <code>IAsyncEnumerable</code> often wrong?	It collects everything in memory and loses streaming: memory grows with the input and the first item is processed only after the last arrives.	ch03 async iasyncenumerable
Why create a TaskCompletionSource with <code>RunContinuationsAsynchronously</code>?	By default <code>SetResult</code> runs awaiting continuations inline on the calling thread: risk of deadlock (locks held by the caller), re-entrancy and slow producers. The option queues continuations to the pool.	ch03 async taskcompletionsource
<code>SetResult</code> vs <code>TrySetResult</code> on a TaskCompletionSource?	<code>SetResult</code> throws if the task is already complete. Use the Try* methods when several paths (reply, timeout, cancel) can complete it.	ch03 async taskcompletionsource
How do you do async initialization when constructors cannot be async?	A static factory <code>static async Task&lt;T&gt; CreateAsync(...)</code>, lazy init guarded by SemaphoreSlim or <code>Lazy&lt;Task&lt;T&gt;&gt;</code>, or init at startup in <code>IHostedService.StartAsync</code>. Never <code>.Result</code> in a constructor.	ch03 async lifetime
A service implements only IAsyncDisposable. What happens if its scope is disposed with <code>using var scope = factory.CreateScope();</code>?	The container throws InvalidOperationException. Use <code>await using var scope = factory.CreateAsyncScope();</code>.	ch03 async iasyncdisposable di
How does PTS release a distributed lock on every exit path?	<pre><code>await using var _ = await _lockService.AcquireForProjectTask(projectTask, Token);</code></pre>The lock is an <code>IAsyncDisposable</code> lease; <code>await using</code> releases it even on exceptions.	ch03 async iasyncdisposable smartcat
Why is <code>Task.Run</code> in an ASP.NET Core action usually pointless?	The request already runs on a pool thread. Moving work to another pool thread and awaiting it adds a context switch and frees nothing.	ch03 async task-run aspnetcore
What is the trap of <code>Task.Factory.StartNew(async () =&gt; ..., TaskCreationOptions.LongRunning)</code>?	The dedicated thread exits at the first await; the rest runs on the pool. Also StartNew returns <code>Task&lt;Task&gt;</code> and needs <code>Unwrap()</code>. Prefer Task.Run or a BackgroundService.	ch03 async task-run
Symptoms of thread-pool starvation?	<ul><li>Latency up sharply while CPU is low</li><li>Probes time out, pods restart</li><li>Thread count grows slowly and steadily</li><li>Thread-pool queue length above zero; timers and consumers lag</li></ul>	ch03 async starvation diagnostics
Which tools confirm thread-pool starvation, and what do you look for?	<code>dotnet-counters monitor -p PID --counters System.Runtime</code> (queue length, thread count); <code>dotnet-stack report</code> or <code>dotnet-dump</code> with <code>clrstack -all</code> / <code>dumpasync</code>: many threads blocked in Task.Wait/.Result under the same frame of your code.	ch03 async starvation diagnostics
Is <code>ThreadPool.SetMinThreads</code> a fix for starvation?	No, a temporary mitigation. It makes the pool start threads without delay but hides the blocking call. The fix is to remove sync-over-async.	ch03 async starvation
Smartcat rule D6: what does it flag, and what is the fix?	Mutable objects passed across async boundaries: classes with public setters reused after await, and shared lists/dictionaries mutated in async methods. MAJOR. Fix: <code>sealed record</code> with <code>With*</code> methods, or pass values.	ch03 async d6 smartcat review
Smartcat rule A9: what is wrong with storing <code>IsAiPdfProcessingEnabled</code> on a background run record?	It snapshots per-request state (from HttpContext) into the run. The flag is frozen at request time and turning it off does not affect queued runs. Fix: store <code>accountId</code>/<code>workspaceId</code> and re-resolve with IFeatureService in the worker. MAJOR.	ch03 async a9 smartcat review
What flows across <code>await</code> automatically?	The <code>ExecutionContext</code>: <code>AsyncLocal&lt;T&gt;</code> values, the tracing <code>Activity</code>, culture and security context. Not the SynchronizationContext unless captured.	ch03 async executioncontext
Smartcat rule D15: what is the async naming rule?	Methods returning Task/Task&lt;T&gt;/ValueTask&lt;T&gt; end with <code>Async</code>; methods with the suffix must return an awaitable. Exempt: external interfaces. NIT. Do not rename old APIs (e.g. <code>ToSleep</code>, <code>Capture</code>) in an unrelated MR.	ch03 async naming d15 smartcat
Where does the <code>CancellationToken</code> parameter go in a method signature?	Last. Public APIs often give it <code>= default</code>. Accepting a token and not passing it down is a bug.	ch03 async naming cancellation
How does <code>SubscriptionPackageResolver</code> (smartcat-ai-agents) stop one cancelled request from failing a shared lookup?	The shared read inside <code>Lazy&lt;Task&lt;T&gt;&gt;</code> runs with <code>CancellationToken.None</code>; each caller awaits <code>pending.Value.WaitAsync(cancellationToken)</code>, so only that caller stops waiting.	ch03 async cancellation smartcat
Interviewer: what follow-up separates a Senior from a Staff answer on sync-over-async?	Ask why ASP.NET Core does not deadlock but still fails, why the pool grows slowly, and how to prove it in production. Staff: explains starvation mechanics, names counters and dump commands, and rejects SetMinThreads as the fix.	ch03 async interviewer
Interviewer: red flags in an async answer?	<ul><li>&quot;await starts a new thread&quot; / &quot;async is faster&quot;</li><li>Task.Run to &quot;make it async&quot;</li><li>One ConfigureAwait(false) as a deadlock fix</li><li>catch (Exception) that swallows cancellation</li><li>GetAwaiter().GetResult() as non-blocking</li></ul>	ch03 async interviewer
Interviewer: a good code-first async question?	Show 15 lines with <code>.Result</code>, <code>list.ForEach(async ...)</code> and <code>_ = SendAsync()</code> in a controller with a scoped repository, and ask &quot;what happens under load?&quot;. Probe: scopes, lost exceptions, restarts, throttling.	ch03 async interviewer
