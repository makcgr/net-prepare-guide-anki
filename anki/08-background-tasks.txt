Why is an in-memory <code>Channel&lt;T&gt;</code> inside a <code>BackgroundService</code> a bad queue for business jobs?	Queued work is lost on every restart or deploy, each pod has its own queue so no other pod can take over, and there are no retries, visibility or fairness.<br><code>BackgroundService</code> is fine as the host of a polling loop.	ch08 background-service queues
Name five requirements to check before choosing a background job tool.	Durability, retries with delay, scheduling, fairness between tenants, visibility/monitoring (also: throughput, transactional enqueue with business data).	ch08 queues design
Why does Smartcat use a MongoDB-backed task queue?	Mongo is already the primary store: tasks survive restarts, can be inserted in the same transaction as business data, hold progress state, are easy to query, and get built-in fairness and canary.	ch08 smartcat queues
Why not put background jobs on Kafka?	Kafka has no per-message delay or retry state, and a slow job blocks its partition. Kafka is for events; tasks are for work.	ch08 kafka queues
Hangfire vs Quartz.NET in one line each?	Hangfire: general durable background jobs with automatic retries and a dashboard (SQL/Redis).<br>Quartz.NET: strong cron/calendar scheduling with triggers and misfire policies.	ch08 hangfire quartz
What is the cloud-queue equivalent of a task capture?	Peek-lock (Azure Service Bus) or visibility timeout (SQS): the message is hidden for a time and reappears if not completed.	ch08 queues lease
Why does a broker queue (SQS, Service Bus) need an outbox for enqueue, while the Smartcat task queue does not?	Enqueue to a broker is a write to a second system (dual write). A Mongo task can be inserted in the same Mongo transaction as the business change.	ch08 smartcat outbox queues
List the Smartcat task states with their values.	Sleep 0, InProgress 1, Closed 2, Manual 3, Suspended 4, ManualKnownIssue 5.	ch08 smartcat state-machine
What does the <code>upTime</code> field mean?	In Sleep: the earliest time the task can be captured. In InProgress: the end of the current lease.	ch08 smartcat basetask
What is <code>CaptureKey</code>?	A random key written at capture: the lease token that identifies the current holder of the task.	ch08 smartcat capture
What does <code>ToSleep(task, delay, reason)</code> do?	Moves to Sleep with <code>upTime = now + delay</code>, resets <code>RecaptureCount</code> and clears the capture.	ch08 smartcat lifecycle
Manual vs ManualKnownIssue?	Both stop automatic capture. ManualKnownIssue suppresses alerts because the failure is known and accepted; put a ticket link in the reason.	ch08 smartcat lifecycle
What happens if a processor path returns without any transition?	The task stays InProgress until the lease expires, then it is recaptured, <code>RecaptureCount</code> grows, and after the limit it fails for no real reason.	ch08 smartcat state-machine code-review
A processor finds the document was deleted. Throw or complete?	Complete with a clear reason (<code>ToComplete(task, &quot;Document was deleted&quot;)</code>). Throwing uses retries and may end in Manual with an alert.	ch08 smartcat lifecycle errors
Describe a task capture as one database operation.	One atomic <code>findOneAndUpdate</code>: filter <code>state = Sleep, upTime &lt;= now</code> (+ canary/fairness), set <code>state = InProgress</code>, new <code>captureKey</code>, <code>upTime = now + captureTime</code>. Only one worker can win it.	ch08 smartcat capture lease
What happens to a captured task when its worker pod is killed?	No transition is written. When <code>upTime</code> passes, another worker recaptures it, <code>RecaptureCount</code> increases, and processing continues from the stored checkpoint.	ch08 smartcat capture recapture
Why is there a recapture limit (6)?	A poison task that kills its worker every time (OOM, stack overflow) would otherwise kill pods forever. After the limit <code>RecaptureCountLimitExceededException</code> stops it.	ch08 smartcat recapture
What does <code>UpdateCapture</code> / <code>UpdateCaptureAsync</code> do and when do you need it?	It extends the lease (heartbeat). Use it in long loops so the task is not recaptured while still being processed (e.g. PTS <code>DeadlineNotificationProcessor</code>).	ch08 smartcat capture lease
Trade-off of the capture time (<code>CaptureDelay</code>)?	Too short: a healthy worker loses the task and two workers run it. Too long: after a crash the task waits long before recovery.	ch08 smartcat lease
What is wrong with this code?<pre><code>var task = await _manager.GetById(taskId);<br>task.ProcessedCount++;<br>await _manager.Update(task);</code></pre>	It modifies a task without capturing it. A worker may hold the task: lost updates, or a Closed task brought back. Change tasks only while holding the capture.	ch08 smartcat capture code-review
How should an outside actor (e.g. a cancel endpoint) signal a running task?	Set a narrow flag field that the processor reads (PTS <code>CancellationIsRequested</code> via <code>UpdateMany</code>). The processor checks it and completes itself; it owns the transitions.	ch08 smartcat cancellation
Why is a cancel endpoint that writes <code>state = Closed</code> directly a bug?	If a worker holds the task, its next <code>ToSleep</code> puts it back to Sleep and the cancel is lost (or it races with a transition).	ch08 smartcat cancellation code-review
Ordinary vs Singleton vs Sticky: one line each.	Ordinary: many tasks, one per unit of work, default.<br>Singleton: one task per Name, schedules and sweeps.<br>Sticky: many tasks with affinity to the worker that has local state.	ch08 smartcat task-types
Which task type supports fairness hash and canary?	Ordinary and Sticky. Singleton has <code>FairnessHash</code> as <code>BsonIgnore</code> and an empty <code>TierKey</code> (no canary).	ch08 smartcat task-types
What makes a Singleton task unique?	Its <code>Name</code>, with a unique index <code>UDX_Name</code>. Capture gives mutual exclusion across pods, so no extra distributed lock is needed.	ch08 smartcat singleton
Sticky task: capture priority for a worker?	1. Own tasks (same <code>StickMarker</code>). 2. New tasks (no marker). 3. Tasks whose <code>StickTimeout</code> passed.	ch08 smartcat sticky
Is stickiness a correctness guarantee?	No, only an optimisation. After <code>StickTimeout</code> another worker takes the task, so it must work without the local data (e.g. download the file again).	ch08 smartcat sticky
Why split &quot;selector singleton&quot; and &quot;ordinary worker tasks&quot;?	One singleton doing all accounts in a loop fails as a whole and backoff delays everyone. The singleton selects and creates per-account ordinary tasks that retry independently (PTS CancelBrokenAcceptedInvitations).	ch08 smartcat singleton design
<code>RetriesCount</code> vs <code>RecaptureCount</code>?	<code>RetriesCount</code>: unhandled exceptions, limited by <code>MaxRetriesCount</code>, then Manual.<br><code>RecaptureCount</code>: lease expired without transition, limit 6.	ch08 smartcat retry
What do <code>runDelay</code>, <code>maxTasks</code>, <code>maxRetriesCount</code> configure?	Polling interval; tasks processed in parallel per instance; unhandled exceptions before Manual.	ch08 smartcat config
How does Singleton retry work?	Consecutive failures in <code>FailureCount</code> with exponential backoff: <code>min(InitialRecoveryTime * GrowthFactor^n, MaxRecoveryTime)</code>; Manual after <code>MaxFailureCount</code>; <code>-1</code> = infinite.	ch08 smartcat singleton backoff
With InitialRecoveryTime 30s, factor 2.0, max 1h: the first four delays?	30s, 60s, 120s, 240s, then growing until capped at 1 hour.	ch08 backoff
Why exponential backoff, and why add jitter?	Backoff reduces load on a dependency while it recovers. Jitter (a random part) stops all workers retrying at the same moment (thundering herd).	ch08 backoff jitter
Which task errors should NOT be retried?	Permanent ones: bad input file, missing entity, disabled feature. They fail every time; complete with a reason or use ManualKnownIssue.	ch08 smartcat errors retry
What is <code>RequiresCompleteRestart</code> / <code>TaskRequiresCompleteRestartException</code> for?	To restart a task from scratch and reset all intermediate state when that state is corrupt.	ch08 smartcat retry
What is the noisy neighbour problem in a task queue?	With FIFO capture, one tenant inserting thousands of tasks makes every other tenant wait behind them.	ch08 fairness
How does the fairness hash fix the noisy neighbour?	Tasks are grouped by the hash and capture goes round-robin over groups instead of strictly by time. <code>SetCompoundFairnessHash(AccountId)</code> makes accounts fair to each other.	ch08 smartcat fairness
What does <code>SetCompoundFairnessHash(new object[] { AccountId, DocumentId })</code> mean?	Fair between accounts first; inside one account, round-robin by document.	ch08 smartcat fairness
Which index does <code>UseFairOrder = true</code> need?	<code>{ state: 1, fairnessHash: 1, upTime: 1 }</code> (<code>IDX_State_FairnessHash_UpTime</code>).	ch08 smartcat fairness indexes
How do you enable fair order on a live task collection?	Phase 1: set the hash on new tasks, create the index in a before-migration, optionally backfill queued tasks. Phase 2: enable <code>UseFairOrder</code>.	ch08 smartcat fairness migrations
What happens when you call <code>SetCompoundFairnessHash</code> on a Singleton?	Nothing: <code>SingletonTask.FairnessHash</code> is <code>BsonIgnore</code>. There is only one task, so there is nothing to be fair between.	ch08 smartcat fairness singleton
Which key should usually be the first fairness key?	The tenant boundary (account). A user id lets one account with many users still flood the queue.	ch08 smartcat fairness
How is <code>IsCanary</code> decided for a task?	At insert, during an active rollout, the manager asks <code>ITaskTierDefiner</code> for the tier of the task's <code>TierKey</code> and stores <code>isCanary</code>. Canary pods capture only canary tasks.	ch08 smartcat canary
Why override <code>TierKey</code> with the account id?	The default is the task id, which splits one customer between old and new code. Account id gives per-customer consistency and limits a bad canary to few customers.	ch08 smartcat canary tierkey
Can you query tasks by <code>tierKey</code> in MongoDB?	No. <code>TierKey</code> is <code>BsonIgnore</code> (computed in C#). Query <code>isCanary</code> instead.	ch08 smartcat canary tierkey
What is wrong with <code>Math.Abs(tierKey.GetHashCode()) % 100</code> for canary tiers?	<code>string.GetHashCode()</code> is randomized per process in .NET Core, so pods disagree on an account's tier. Use a stable hash (MD5, SHA-256, XxHash) of the bytes.	ch08 smartcat canary hashing t18
What does review rule T18 ask for?	For new hashing-relevant code shared across pods, a test that computes the value in two different processes and asserts the same result.	ch08 testing t18 hashing
Query the canary distribution of a task collection.	<pre><code>db["AsyncTasks.X"].aggregate([{ "$group": { "_id": "$isCanary", "count": { "$sum": 1 } } }])</code></pre>	ch08 smartcat canary monitoring
Capture index for an Ordinary task without fair order?	<code>{ state: 1, upTime: 1 }</code> (<code>IDX_State_UpTime</code>).	ch08 smartcat indexes
Indexes for a Sticky task collection?	<code>{ state: 1, stickMarker: 1, upTime: 1 }</code> and <code>{ state: 1, stickTimeout: 1, upTime: 1 }</code>.	ch08 smartcat sticky indexes
How does PTS guarantee one unfinished ApplyAssignmentTemplate task per project task?	A unique index on <code>projectTaskId</code> with a partial filter <code>isFinished == false</code>. A duplicate insert throws duplicate key; <code>TryAddTask</code> catches it and returns false.	ch08 smartcat indexes idempotency
Why a unique index instead of &quot;check if a task exists, then insert&quot;?	Check-then-insert is a TOCTOU race: two requests both see &quot;none&quot; and both insert (review rule A28).	ch08 a28 idempotency
Why is a task processor at-least-once?	A worker can do the side effect and die before the transition, a short lease can let a second worker in, and a retry repeats work before the failing line.	ch08 idempotency at-least-once
Name three ways to make a task step safe to repeat.	Checkpoint after each step (<code>NextIteration</code>); idempotent writes (set not increment, upsert, unique keys); idempotency keys for external calls; re-read state before acting.	ch08 idempotency
What is wrong here?<pre><code>account.Credits += task.Amount;<br>await _accounts.Save(account);<br>await TasksManager.ToComplete(task, "Credited");</code></pre>	A crash before <code>ToComplete</code> credits twice on recapture. Key the effect by the task id (e.g. a ledger entry with a unique index on task id).	ch08 idempotency code-review
What is review rule T14 for task code?	A replay test: run the same step twice with the same input and assert a single side effect.	ch08 testing t14
Why is <code>IMemoryCache</code> dangerous in task processing (rule A18)?	It is per pod. A task moves between pods, so another pod does not see the cached decision. Read the authoritative source or use a distributed cache.	ch08 a18 cross-pod
What is review rule A3 about?	Cross-pod state in object identity: lambdas, <code>Func&lt;&gt;</code> or anonymous types used as ids differ per pod. Use stable string names.	ch08 a3 cross-pod
What is review rule A4 about?	Background work keyed only by <code>runId</code> can cross tenants. Always include <code>(accountId, workspaceId)</code> in routing keys and queries.	ch08 a4 cross-pod security
What is review rule A11 about?	Lock renewal must classify errors: &quot;lock lost&quot; (logical, give up) is different from an infrastructure glitch like <code>MongoConnectionException</code> (retry with backoff).	ch08 a11 locks
Where must a long task keep its progress?	In the task document (e.g. <code>NextIteration</code>, <code>LastProcessedDate</code>), not in statics, per-pod memory or local disk.	ch08 smartcat cross-pod
You add a field to a task model. How do you keep it backward compatible?	Make it optional (<code>[BsonIgnoreIfDefault]</code> or nullable) and handle the default for tasks created by old code; old and new code read the same documents during deploys and canaries.	ch08 smartcat compatibility
How do you change a task's type (e.g. Ordinary to Singleton)?	New collection, migrate data, switch the processor. Do not reuse the old collection.	ch08 smartcat compatibility
Compatibility trap when you change processing steps (e.g. group size)?	New code must still interpret checkpoints written by old code (e.g. <code>NextIteration = 3</code> under the old group size).	ch08 smartcat compatibility
Query: tasks stuck in progress?	<pre><code>db["AsyncTasks.X"].find({ "state": 1, "upTime": { "$lt": ISODate("...") } })</code></pre>InProgress long after the lease should have ended.	ch08 smartcat monitoring
Query: tasks that keep losing their lease?	<pre><code>db["AsyncTasks.X"].find({ "recaptureCount": { "$gte": 5 } })</code></pre>Crashing workers or a too short capture time.	ch08 smartcat monitoring
Which states mean a task is stopped and may need a human?	Manual (3), Suspended (4), ManualKnownIssue (5): <code>{ state: { $in: [3, 4, 5] } }</code>.	ch08 smartcat monitoring
Why must transition reasons be clear sentences?	In an incident, <code>reason</code> is read first. A good reason tells support what happened without logs.	ch08 smartcat monitoring
Which task fields help find expensive or strange tasks?	<code>totalCapturedTime</code>, <code>totalCaptureCount</code>, <code>capturedAt</code>, <code>activityTraceId</code> (link to the creating trace), <code>responsibleTeams</code>.	ch08 smartcat monitoring telemetry
A task queue grows. Name four things to check.	Ready depth and oldest age; one account flooding (group by account, fairness on?); recapture and manual rates; missing capture index or slow dependency; worker count and <code>maxTasks</code>.	ch08 smartcat operations
Why should a test not call a protected <code>ProcessTaskItemImpl</code> by reflection?	It pins the implementation; renames break at runtime. Test through the public entry point, or extract the step into a service you can test directly.	ch08 testing reflection
What does review rule T17 require when a task adds retry?	A test that simulates N+1 failures and asserts the task gives up (manual mode / budget exceeded).	ch08 testing t17 retry
Interviewer: a good opening design question for background tasks?	&quot;Export a project with 50,000 documents on 6 pods with daily deploys.&quot; Then add: pod dies, one customer starts 3,000 exports, storage returns 503, canary on 5% of customers.	ch08 interviewer
Interviewer: which probe separates Senior from Staff on task design?	&quot;How does the canary decide customer X is in 5%, and is that the same on every pod? What happens to tasks the old version started?&quot; Staff talks about stable hashing and model compatibility.	ch08 interviewer canary
Interviewer: red flags in a background-task answer?	<code>Task.Run</code> or an in-memory queue for critical work; a lock around the whole job without lease expiry; cancel by writing Closed directly; unlimited retries; <code>GetHashCode()</code> for cross-pod routing.	ch08 interviewer
