Thread vs thread pool vs Task: one line each.	Thread: an OS thread you create and own. Thread pool: shared, reusable worker threads. Task: a unit of work or promise, usually run on the pool, with results, exceptions and cancellation built in.	ch04 threading basics
When do you create a dedicated <code>Thread</code> in a modern service?	Almost never. Only for a blocking loop that runs for the whole process life (or special apartment/priority needs). Usually a <code>BackgroundService</code> that is async all the way is better.	ch04 threading basics
Name the three separate problems of shared memory between threads.	<ul><li>Atomicity: seeing half a value, read-modify-write</li><li>Visibility: a write not seen by another core, or cached in a register</li><li>Ordering: compiler/JIT/CPU reorder reads and writes</li></ul>	ch04 memory-model
Which reads and writes are atomic in .NET?	References and primitives up to the native word size (int, bool, references; long/double on 64-bit). Larger structs (Guid, decimal, custom structs) can be torn. <code>count++</code> is never atomic.	ch04 memory-model atomicity
Why can a concurrency bug appear only on ARM64?	x86 has a strong memory model that hides many reorderings. ARM64 (Apple Silicon, AWS Graviton) is weaker, so missing barriers become visible.	ch04 memory-model
What does <code>volatile</code> guarantee in C#?	A volatile read has acquire semantics, a volatile write has release semantics, and the JIT must really read memory each time. Enough for one writer publishing a flag or reference.	ch04 memory-model volatile
What does <code>volatile</code> NOT give you?	Atomic read-modify-write (<code>count++</code> is still a race), and protection against store-then-load reordering. Use Interlocked or a lock.	ch04 memory-model volatile
Why is double-checked locking tricky?	You need both checks; on weak memory models another thread can see the reference before the constructor's writes; and variants like <code>_x = new X(); _x.Init();</code> publish an unready object. It works on CoreCLR due to runtime guarantees, but use <code>Lazy&lt;T&gt;</code>.	ch04 memory-model lazy
<code>LazyThreadSafetyMode.ExecutionAndPublication</code> vs <code>PublicationOnly</code>?	ExecutionAndPublication: factory runs exactly once (default). PublicationOnly: factory may run many times, first result wins, no lock. Use the second only for cheap, pure factories.	ch04 lazy
What is the exception trap of <code>Lazy&lt;T&gt;</code> in the default mode?	If the factory throws, the exception is cached: every later <code>.Value</code> throws it again. Wrong for transient failures. PublicationOnly does not cache exceptions; for async, remove a failed <code>Lazy&lt;Task&lt;T&gt;&gt;</code>.	ch04 lazy
How does <code>CachedModelPriceProvider</code> (smartcat-ai-agents) let readers avoid locks?	The writer builds a new dictionary under a <code>SemaphoreSlim(1,1)</code> gate and publishes it with <code>Volatile.Write</code>; readers use <code>Volatile.Read</code>. The &quot;loaded&quot; timestamp is set only after the swap.	ch04 snapshot smartcat
Why must the &quot;cache is fresh&quot; timestamp be written AFTER the new snapshot is published?	Otherwise concurrent callers see &quot;fresh&quot;, skip the gate, and read the old or empty data. In the pricing provider that would charge the fallback price.	ch04 snapshot race
What does a <code>lock</code> statement on an object compile to?	<pre><code>bool lockTaken = false;<br>try { Monitor.Enter(obj, ref lockTaken); /* body */ }<br>finally { if (lockTaken) Monitor.Exit(obj); }</code></pre>	ch04 lock monitor
Besides mutual exclusion, what does <code>Monitor</code> give you?	A full memory barrier on enter and exit, so writes inside the lock are visible to the next holder. It is re-entrant and thread-affine.	ch04 lock monitor
Which objects must you never lock on, and why?	<code>this</code>, a <code>Type</code> (<code>typeof(X)</code>), or a <code>string</code>: other code can lock on the same object (interned strings are process-wide). Lock on a private readonly object.	ch04 lock
What is <code>System.Threading.Lock</code> (.NET 9)?	A dedicated lock type. <code>lock (_lock)</code> on it uses <code>EnterScope()</code> (a ref struct disposed at the end). Faster than Monitor; the compiler warns if you convert it to object.	ch04 lock dotnet9
Why is <code>await</code> inside <code>lock</code> not allowed (CS1996)?	Monitor is thread-affine: the continuation may resume on another thread, which cannot exit a lock it does not own. And holding a lock across I/O blocks everyone else for the whole round trip.	ch04 lock async
What is the async replacement for <code>lock</code>?	<code>SemaphoreSlim(1, 1)</code>: <code>await WaitAsync(ct)</code> before <code>try</code>, <code>Release()</code> in <code>finally</code>.	ch04 semaphoreslim async
What is wrong here?<br><pre><code>try<br>{<br>    await _mutex.WaitAsync(ct);<br>    await WorkAsync(ct);<br>}<br>finally { _mutex.Release(); }</code></pre>	If <code>WaitAsync</code> is cancelled, <code>finally</code> releases a slot that was never taken, and the count goes above 1: two callers can enter. Wait before the try.	ch04 semaphoreslim
Is <code>SemaphoreSlim</code> re-entrant?	No. If a method holding it calls another method that also waits on it, the flow waits forever. Monitor (<code>lock</code>) is re-entrant.	ch04 semaphoreslim deadlock
What happens if <code>Release()</code> is not in <code>finally</code>?	One exception leaves the semaphore at zero; every later caller waits forever (or until its timeout).	ch04 semaphoreslim
What does <code>Interlocked.CompareExchange(ref x, newValue, comparand)</code> do and return?	Atomically sets x to newValue only if x equals comparand, and returns the original value. It is the compare-and-swap base of lock-free loops.	ch04 interlocked
When is <code>Interlocked</code> not enough?	When an invariant links two or more fields. Use a lock, or one immutable object holding both, swapped with <code>Interlocked.Exchange</code>.	ch04 interlocked
When is <code>ReaderWriterLockSlim</code> worth it, and what are its limits?	Many readers, rare writers, non-trivial read sections. Limits: thread-affine (no await), more overhead than lock, upgradeable mode is easy to misuse. A snapshot swap or ConcurrentDictionary is often simpler.	ch04 rwlock
Does <code>ConcurrentDictionary.GetOrAdd(key, factory)</code> run the factory once?	Not guaranteed. The factory runs outside the lock; under contention several threads can run it. Only one result is stored and returned. Same for AddOrUpdate's update delegate.	ch04 concurrentdictionary
How do you make <code>GetOrAdd</code> safe when the factory is expensive or has side effects?	<pre><code>_map.GetOrAdd(key, k =&gt; new Lazy&lt;Task&lt;V&gt;&gt;(<br>    () =&gt; LoadAsync(k),<br>    LazyThreadSafetyMode.ExecutionAndPublication)).Value;</code></pre>The factory only creates a cheap Lazy; only the stored one is started.	ch04 concurrentdictionary lazy
Smartcat example of the correct single-flight shape?	<code>SubscriptionPackageResolver</code> in smartcat-ai-agents: <code>ConcurrentDictionary&lt;string, Lazy&lt;Task&lt;SubscriptionLookup&gt;&gt;&gt;</code>, entry removed in finally, callers await <code>WaitAsync(ct)</code>.	ch04 concurrentdictionary smartcat
Why is <code>if (!dict.ContainsKey(k)) dict[k] = v;</code> a race even on a ConcurrentDictionary?	It is two operations (check, then act). Another thread can add between them. Use <code>TryAdd</code>, <code>GetOrAdd</code>, <code>AddOrUpdate</code> or <code>TryUpdate</code>.	ch04 concurrentdictionary race
Is <code>ConcurrentDictionary&lt;string, List&lt;int&gt;&gt;</code> thread-safe?	The dictionary is; the lists inside are not. Two threads calling <code>dict[k].Add(...)</code> corrupt a list. Use immutable values or concurrent collections as values.	ch04 concurrentdictionary
When is <code>ConcurrentBag&lt;T&gt;</code> a good fit?	Unordered results, especially when the same threads add and take (it keeps per-thread lists). Fine for collecting results of parallel bodies, as in PTS VendorAssignmentFixTaskProcessor.	ch04 concurrent-collections
<code>BlockingCollection&lt;T&gt;</code> vs <code>Channel&lt;T&gt;</code>?	BlockingCollection blocks threads (sync Take, GetConsumingEnumerable). Channel is the async producer/consumer queue (ReadAsync, ReadAllAsync). In async code use Channel.	ch04 channels concurrent-collections
Why use a bounded channel?	Backpressure: when full, the producer waits (or items are dropped by policy) instead of memory growing until the pod is killed.	ch04 channels backpressure
Name the four <code>BoundedChannelFullMode</code> values.	<code>Wait</code> (default, backpressure), <code>DropNewest</code>, <code>DropOldest</code>, <code>DropWrite</code> (drop the item being written).	ch04 channels
Why keep <code>AllowSynchronousContinuations = false</code> (the default) on a channel?	With true, a write can run the reader's continuation inline on the writer's thread: faster, but the same deadlock and re-entrancy risks as a TaskCompletionSource without RunContinuationsAsynchronously.	ch04 channels
A channel consumer is a BackgroundService. Name three must-haves.	<ul><li>A new DI scope per item (<code>CreateAsyncScope</code>)</li><li>Catch and log per item so one bad item does not stop the loop</li><li>Accept that in-memory items are lost on restart, or use a persisted task / Kafka</li></ul>	ch04 channels backgroundservice
What happens when an exception escapes <code>BackgroundService.ExecuteAsync</code>?	The service stops and, by default since .NET 6, the whole host stops (BackgroundServiceExceptionBehavior.StopHost).	ch04 backgroundservice
How does <code>NarrationAgent</code> (smartcat-ai-agents) configure its channel?	Bounded with configured capacity, <code>FullMode = Wait</code>, <code>SingleWriter = false</code>, <code>SingleReader = true</code>, <code>AllowSynchronousContinuations = false</code>.	ch04 channels smartcat
When are <code>Parallel.For</code> / PLINQ the right tool?	Only for CPU-bound work on in-memory data. They block threads; never use them for I/O. In a web service, limit the degree so one request does not take all cores.	ch04 parallel plinq
Name the three common shapes of race conditions.	<ul><li>Read-modify-write (<code>x++</code>, balance updates)</li><li>Check-then-act (&quot;if not exists, create&quot;)</li><li>Unsafe publication / lazy init</li></ul>	ch04 race-condition
What is the first question when reviewing code for races?	What is shared and mutable? Static fields, singleton fields, captured lambda variables, objects handed to parallel work. No shared mutable state means no race.	ch04 race-condition review
What are the four conditions for a deadlock?	Mutual exclusion, hold-and-wait, no preemption, circular wait. Break any one; in practice break circular wait with a fixed lock order.	ch04 deadlock
How do you avoid deadlock in <code>Transfer(a, b)</code> / <code>Transfer(b, a)</code>?	Always take the locks in one global order, for example by account id. Also: one lock at a time when possible, no unknown code under a lock, timeouts.	ch04 deadlock
What is a livelock, and the usual fix?	Threads are not blocked but keep reacting to each other without progress (both wait 100 ms and retry together). Fix: random jitter in retries.	ch04 livelock
What is wrong with a mutable field in a DI singleton?	All concurrent requests share it. Per-call state in a field leaks between requests (one request uses another's value). Keep per-call state in locals.	ch04 di singleton
What is a captive dependency, and how does Smartcat rate it?	A singleton that takes a scoped service in its constructor: the scoped object lives forever and is shared. Rule A1, BLOCKER.	ch04 di singleton smartcat review
Smartcat rule A23: what does it flag?	A singleton that reads/writes an AsyncLocal field, or keeps HttpContext state in a field. Fix: explicit AsyncLocal contract with a comment plus a test that two concurrent requests do not see each other's state. MAJOR.	ch04 di singleton smartcat review
Why does <code>[ThreadStatic]</code> break in async code?	After await the continuation may run on another thread with another value. Pool threads are reused, so one request's value is seen by the next. Also the initializer runs only on the first thread.	ch04 threadstatic asynclocal
Does a value set in an AsyncLocal inside an async method flow back to the caller?	No. The runtime restores the caller's ExecutionContext when the async method returns. Child flows see the parent's value at the time they started.	ch04 asynclocal
Why is a mutable object in an <code>AsyncLocal&lt;T&gt;</code> dangerous?	The ExecutionContext copies only the reference. Every flow that captured it (including background work started from the request) shares and mutates the same object. With tenant data this is a cross-tenant leak.	ch04 asynclocal security
Smartcat rule S5: what is flagged, and what is the correct alternative?	<code>static readonly AsyncLocal&lt;T&gt;</code> with a public setter, or ambient-context classes without a scope owner. MAJOR. Use scoped DI or <code>HttpContext.Items[&quot;key&quot;]</code> set once per request.	ch04 asynclocal s5 smartcat review
What makes <code>ClientToolsAmbientContext</code> an acceptable AsyncLocal use?	Internal, no public setter, set by one owner through <code>Bind(provider)</code> which returns an IDisposable that restores the previous value. It covers the background path with no HttpContext.	ch04 asynclocal smartcat
Why is immutability a concurrency tool?	An object that never changes after construction is thread-safe without locks. To change it, build a new one and swap the reference (<code>Volatile.Write</code> / <code>Interlocked.Exchange</code>).	ch04 immutability
Why does <code>lock</code> protect nothing in a Smartcat service with three pods?	Each pod has its own memory and its own lock. Two pods run the same code at the same time against the same Mongo document. Coordination must live in the shared store.	ch04 distributed
What is wrong here when two pods run it?<br><pre><code>var s = await _scopes.Find(x =&gt; x.Id == id).SingleAsync(ct);<br>s.Progress += inc;<br>await _scopes.ReplaceOneAsync(x =&gt; x.Id == id, s);</code></pre>	Lost update: both pods read the same value and the second write overwrites the first. Use an atomic update: <code>FindOneAndUpdate(filter, Update.Inc(x =&gt; x.Progress, inc))</code>.	ch04 distributed mongo atomic
How do you express &quot;change only if the state is still Pending&quot; across pods?	Put the condition in the filter: <code>UpdateOne(Id == id &amp; Status == Pending, Set(Status, Running))</code>. <code>ModifiedCount == 1</code> means you won.	ch04 distributed mongo atomic
How does optimistic concurrency with a version field work?	Read the document and its Version, build the new state, write with filter <code>Id == id &amp; Version == read</code> and Version + 1. MatchedCount 0 means someone else won: reload and retry, or report a conflict.	ch04 distributed optimistic
Why is <code>if (current.Version != expected) throw;</code> in C# not enough?	Two writers can pass the check at the same time. Only the version in the write filter makes check and write one atomic step (as MongoBriefTemplates in smartcat-ai-agents comments).	ch04 distributed optimistic smartcat
Smartcat rule A10: what goes wrong when you add a Version field to an existing collection?	Old documents have no field, so <code>Eq(Version, 0)</code> does not match them. Backfill in a migration, or filter <code>Or(Eq(Version, current), Exists(false))</code>. MINOR.	ch04 distributed optimistic smartcat review
What is TOCTOU, and the Smartcat fix for &quot;check name free, then insert&quot; (A28)?	Time of check to time of use: the condition changes between check and act. Fix: rely on a unique index, catch DuplicateKey, map it to a domain error. MINOR.	ch04 distributed toctou smartcat review
Smartcat rule A27: what is wrong with a unique index on <code>Name</code> alone?	It is global across tenants. Include the tenant: <code>(workspaceId, name)</code> or <code>(accountId, key)</code>.	ch04 distributed mongo smartcat review
Smartcat rule A22: what does it flag, and the fixes?	A loop of UpdateOne/DeleteOne calls for one domain intent (not atomic, half-done states). Fix: UpdateMany with ArrayFilters, or a transaction with IClientSessionHandle. MAJOR.	ch04 distributed mongo smartcat review
Six things a distributed lock must do.	<ul><li>Acquire atomically</li><li>Expire (TTL/deadline)</li><li>Use one clock (server time)</li><li>Renew for long work</li><li>Tell the holder when lost</li><li>Release on every path</li></ul>	ch04 distributed-lock
How does the FDA distributed semaphore avoid clock skew?	The acquire and renew updates compute expiry with <code>$$NOW</code> (Mongo server time) inside one atomic FindOneAndUpdate pipeline. Pod clocks are not used.	ch04 distributed-lock smartcat
What is a lease token, as in the FDA DistributedSemaphore?	A CancellationToken given to the guarded work. It is cancelled when the lifetime runs out, the caller cancels, or renewal finds the slot lost, so the work stops instead of running unprotected.	ch04 distributed-lock smartcat
Smartcat rule A11: what must a lock renewer do with exceptions?	Classify them: &quot;lock lost&quot; (logical: stop the work) vs &quot;infrastructure glitch&quot; like MongoConnectionException (retry on the next tick). Treating every exception as lost is MAJOR.	ch04 distributed-lock a11 smartcat review
Why is <code>$&quot;Project_{id}_{stage.GetHashCode()}&quot;</code> a bad distributed lock key?	<code>HashCode.Combine</code> and <code>string.GetHashCode</code> are randomized per process, so each pod computes a different key and the pods do not exclude each other. Build keys from stable values (ids, numbers).	ch04 distributed-lock hashing
What can a lease NOT protect against, and the stronger tool?	A holder that pauses longer than the lease (GC, frozen container) and then writes after another pod took over. Use fencing: a growing number per acquisition, checked in the write filter.	ch04 distributed-lock fencing
Smartcat task processing: why must you never modify a task without capturing it?	Capture is the cross-pod lock: an atomic update to InProgress with a new CaptureKey and UpTime. <code>GetById</code> + modify + <code>Update</code> races with the pod that captured it.	ch04 distributed tasks smartcat
Why is per-pod <code>IMemoryCache</code> risky (Smartcat rule A18)?	Each pod has its own copy: inconsistent answers and <code>Remove(key)</code> only clears the local pod. In cross-pod or checkpoint-critical flows use IDistributedCache (Redis) or read the source. MAJOR.	ch04 distributed cache smartcat review
When is a per-pod IMemoryCache acceptable?	Read-mostly reference data with a short, documented staleness window, e.g. the 10-minute workspace subscription cache in SubscriptionPackageResolver (a named constant, rule A38).	ch04 distributed cache smartcat
What is an idempotency key, and why do consumers need one?	A stable id of the request/message stored with its side effect (unique index). Kafka redelivers, clients retry, users click twice: a duplicate must have no extra effect.	ch04 idempotency
Is <code>$inc Balance</code> in a Kafka handler idempotent?	No. A redelivered message increments twice. Record the MessageId under a unique index in the same transaction, or make the update conditional on the id not yet applied.	ch04 idempotency kafka
Smartcat rule A34: what is required for a side-effecting run triggered by a UI confirmation?	Pass an <code>idempotencyKey</code> derived from the confirmation id to the workflow client, and verify the backend de-duplicates. BLOCKER.	ch04 idempotency smartcat review
Smartcat rule T14: what test does a state-update fix need?	A replay test: process the same input (messageId/runId/idempotencyKey) twice and assert a single side effect. MAJOR.	ch04 idempotency testing smartcat review
Smartcat rule T3: what test does new lock/SemaphoreSlim/Monitor code need?	At least one test with deliberate contention using <code>Task.WhenAll</code> or <code>Parallel.ForEachAsync</code>. MAJOR.	ch04 testing t3 smartcat review
How do you make a &quot;loads only once&quot; contention test deterministic?	Hold the fake dependency open with a TaskCompletionSource, start many callers, then release it; assert one call and correct results. No sleeps.	ch04 testing
Name four techniques for deterministic concurrency tests.	<ul><li>TaskCompletionSource gates in fakes</li><li>Barrier / CountdownEvent to release threads together</li><li>FakeTimeProvider for leases and timeouts</li><li>Replay tests; ephemeral Mongo for atomicity and unique indexes</li></ul>	ch04 testing
Interviewer: a good two-step concurrency question?	Give a singleton cache class; ask to make it correct for many threads, then for many pods. Step two shows who thinks beyond <code>lock</code>: atomic updates, versions, unique indexes, distributed cache.	ch04 interviewer
Interviewer: what separates a Senior from a Staff answer on distributed locks?	Senior: atomic acquire, expiry, release. Staff: server clock, renewal with error classification, lease token, stable keys, the GC-pause problem and fencing, and how to test it with fake time.	ch04 interviewer distributed-lock
Interviewer: red flags in a concurrency answer?	<ul><li>&quot;Add lock everywhere&quot; / &quot;make it volatile&quot;</li><li>Workarounds for await in lock</li><li>Lock without expiry or with pod clocks</li><li>Read-check-write as the uniqueness guard</li><li>Thread.Sleep in tests</li></ul>	ch04 interviewer
